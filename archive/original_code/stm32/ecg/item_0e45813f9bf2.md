## 一、先看整体：数据是怎么流的

```
 ADS1292                STM32                          PC / 香橙派
┌─────────┐          ┌──────────────────────────┐    ┌──────────┐
│ 电极信号 │          │                          │    │          │
│    ↓    │          │  ┌────────────────────┐  │    │          │
│  ADC转换 │          │  │ ① DRDY中断服务程序  │  │    │          │
│    ↓    │  DRDY↓   │  │   读9字节 → 取CH1   │  │    │          │
│ 数据就绪 ├─────────►│  │   ↓                │  │    │          │
│    ↓    │          │  │   放进环形缓冲      │  │    │          │
│ 等主机来读│  SPI     │  └──────────┬─────────┘  │    │          │
│         │◄────────►│             ↓            │    │          │
└─────────┘  9字节   │  ┌────────────────────┐  │UART│          │
                     │  │ ② 主循环 while(1)   ├──┼───►│ 串口助手  │
   每 2ms 一次        │  │   从缓冲取一个      │  │    │ 或Python  │
   (500 SPS)         │  │   转成文本发串口     │  │    │          │
                     │  └────────────────────┘  │    │          │
                     └──────────────────────────┘    └──────────┘
```

**一句话：** ADS1292 每 2 毫秒把 DRDY 引脚拉低一次告诉 STM32「数据好了」，
STM32 在中断里飞快把数据读进内存排队，主循环慢慢把队列里的数发到串口。

**为什么要分成两半？** 因为这两件事速度差太多：

| 事情 | 耗时 | 能不能等 |
|---|---|---|
| 读 9 字节 SPI | 128 µs | 不能等，等了数据就被下一个覆盖 |
| 发一行串口 | 700 µs | 可以等，慢一点没关系 |

如果把串口发送也塞进中断里，一次中断就要 128+700 = 828 µs。
虽然还没超过 2 ms，但一旦你以后想加滤波、加校验、改波特率，立刻就爆了。
分开写，采样时序永远由硬件（DRDY）决定，跟串口快慢完全无关。

## 二、三个必须先懂的概念

### 概念 1：DRDY 是什么

DRDY = **D**ata **R**ea**dy**，是 ADS1292 的一个**输出**引脚（接到 STM32 的 PA0）。

芯片内部每 2 ms 完成一次 AD 转换，转换完就把 DRDY 从高**拉低**，意思是
「新数据在寄存器里了，你来读吧」。你读完，它自己变回高，等下一次。

```
DRDY   ────┐   ┌──────────┐   ┌──────────┐   ┌───
           └───┘          └───┘          └───┘
           ↑              ↑              ↑
        第1个数据       第2个数据       第3个数据
        ←──── 2 ms ────→
```

我们把 PA0 配成**下降沿触发中断**，所以每次 DRDY 掉下来，CPU 就自动跳进
`HAL_GPIO_EXTI_Callback()` 去读数。不用自己去轮询查引脚状态。

### 概念 2：RDATAC 模式

ADS1292 有两种读数据的方式：

| 模式 | 怎么读 | 命令 |
|---|---|---|
| RDATA（单次） | 每次都要先发一条 `RDATA` 命令，再读 9 字节 | `0x12` |
| **RDATAC（连续）** | **不用发命令，直接读 9 字节** | `0x10` |

我们用 RDATAC，中断里少发一个字节，省事。

**但有个大坑：** 芯片**上电默认就在 RDATAC 模式**，而在这个模式下，
所有的 `RREG`（读寄存器）/ `WREG`（写寄存器）命令**会被芯片当成数据请求直接忽略**。

所以初始化第一件事必须是发 `SDATAC`（`0x11`）退出连续模式，否则你后面写的
11 个寄存器**一个都写不进去**，而且不会报错，你只会看到一堆乱数据。
这是新手最常踩的坑，代码第 5 步就是干这个的。

### 概念 3：中断优先级 3 vs SysTick 的 15

你在 CubeMX 里把 EXTI0 的抢占优先级设成了 **3**。
HAL 库的系统滴答 SysTick 优先级是 **15**。

**Cortex-M 的规则：数字越小优先级越高。** 3 < 15，所以：

> EXTI0 中断执行期间，SysTick **无法**打断它。

后果是：**中断里 `HAL_GetTick()` 返回的值是冻结的，不会往前走。**

这会影响所有依赖 tick 的 HAL 函数，但**影响程度分两种，要分清楚**：

#### 第一种：真的会永远卡死 —— `HAL_Delay`

`stm32f1xx_hal.c:371`：

```c
__weak void HAL_Delay(uint32_t Delay)
{
  uint32_t tickstart = HAL_GetTick();
  uint32_t wait = Delay;
  if (wait < HAL_MAX_DELAY) { wait += (uint32_t)(uwTickFreq); }
  while ((HAL_GetTick() - tickstart) < wait) { }   // ← 唯一退出条件就是 tick 前进
}
```

这个循环**没有任何别的退出路径**。tick 冻结 = 无限循环，整块板子死掉。

**所以中断里绝对不能调 `HAL_Delay`**，微秒延时必须用 DWT（见 4.4）。

#### 第二种：能正常工作，但丢了超时保护 —— `HAL_SPI_TransmitReceive`

`stm32f1xx_hal_spi.c:1323`：

```c
while ((hspi->TxXferCount > 0U) || (hspi->RxXferCount > 0U))
{
    if (TXE && TxXferCount > 0 && txallowed) { 写DR; TxXferCount--; }
    if (RXNE && RxXferCount > 0)             { 读DR; RxXferCount--; }
    if (((HAL_GetTick() - tickstart) >= Timeout) && ...) return HAL_TIMEOUT;   // 永远不成立
}
```

**注意退出条件是计数器归零，由硬件 TXE/RXNE 标志驱动，跟 tick 无关。**
SPI 硬件照常收发，9 个字节传完计数器归零，循环正常退出。

**所以在中断里用 HAL 的 SPI 函数是能读到数据的，不会卡死。**
失去的只是那行超时判断：硬件真出故障时（芯片没供电、SCK 断线），
本该 100 ms 后返回 `HAL_TIMEOUT` 的调用会变成无限等待 —— 从"报错"退化成"假死"。

（顺带一提，收尾函数 `SPI_WaitFlagStateUntilTimeout`（`:3579`）里 ST 加了软件
计数器兜底，注释写着 *"to avoid blocking issue if Systick is disabled"*，
那一段即使 tick 冻结也能超时退出。但主传输循环没有这个兜底，保护只有半套。）

#### 第三个隐患：`__HAL_LOCK` 重入

`HAL_SPI_TransmitReceive` 开头会上锁（`:1215`）：

```c
if (hspi->Lock == HAL_LOCKED) { return HAL_BUSY; }
else                          { hspi->Lock = HAL_LOCKED; }
```

如果**主循环正在用 SPI 时中断插进来**，中断里的调用会立刻返回 `HAL_BUSY`，
一个字节都没读。而这种返回值多半没人检查，结果就是**静默丢一个采样点**。

我们的主循环只发串口不碰 SPI，所以现在碰不到。但这是个埋着的雷。

#### 结论

| | 中断里能用吗 | 说明 |
|---|---|---|
| `HAL_Delay` | ❌ **绝对不行** | 真·无限循环，板子死 |
| `HAL_SPI_TransmitReceive` | ⚠️ 能用但不推荐 | 正常工作，但超时保护失效 + 有 `HAL_BUSY` 重入风险 |
| 自己写的 `spi_xfer` | ✅ | 无锁、无 tick 依赖、最快 |
| 自己写的 `delay_us`（DWT） | ✅ | 硬件计数器，跟中断优先级无关 |

本代码选了自己写的版本（见 4.4 和 4.6）。

**如果你更想用 HAL**，还有一条路：把 SysTick 提到最高优先级，
改 `Core/Inc/stm32f1xx_hal_conf.h:132`：

```c
#define  TICK_INT_PRIORITY            0U    /* 原来是 15U */
```

这样 SysTick 能抢占 EXTI0，`HAL_GetTick()` 在中断里正常走，所有 HAL 函数
恢复正常语义。代价是 SysTick 每毫秒打断一次 SPI 读，加几微秒抖动——
对我们无所谓，ADS1292 的数据一直挂在寄存器里等你读，晚几微秒不会丢。

CubeMX 生成的框架里，你写的代码只能放在 `USER CODE BEGIN/END` 之间

| 区块名 | 放了什么 |

## 四、逐段详解

### 4.1 宏定义区（USER CODE PD）

#### 模式开关

```c
#define TEST_SIGNAL_MODE   1
```

`1` = 用芯片内部产生的 1Hz 方波测试信号（**不用接电极**，专门验证
「SPI 通不通 + 数据解析对不对 + 串口输出对不对」这条链路）。
`0` = 正常从电极采集心电。

**先用 1 跑通，再改 0。** 因为接电极时波形不好看，你分不清是电极问题还是程序问题；
测试信号是芯片内部产生的标准方波，值是死的（±20960），错了一眼就能看出来。

#### 引脚定义

```c
#define ADS_CS_PORT     GPIOA      // 片选     PA4
#define ADS_START_PORT  GPIOB      // 启动转换 PB0
#define ADS_RST_PORT    GPIOB      // 复位     PB1
#define ADS_DRDY_PORT   GPIOA      // 数据就绪 PA0（输入，中断）
```

这几个是从原理图来的。写成宏是为了以后改线不用满文件找。

#### 片选宏 —— 注意这个 `do { } while(0)`

```c
#define ADS_CS_L()   HAL_GPIO_WritePin(ADS_CS_PORT, ADS_CS_PIN, GPIO_PIN_RESET)

#define ADS_CS_H()   do { delay_us(10);                                             \
                          HAL_GPIO_WritePin(ADS_CS_PORT, ADS_CS_PIN, GPIO_PIN_SET); \
                     } while (0)
```

**你之前问过「CS 不是应该用 `HAL_GPIO_WritePin` 控制吗，怎么直接 `ADS_CS_H()`」——
就是这里：宏展开后还是 `HAL_GPIO_WritePin`，只是前面多塞了一个延时。**

为什么要多塞延时？手册 8.5.1.1 规定：**CS 拉高之前必须等 4 个 tCLK**。
tCLK = 1/512kHz = 1.953 µs，4 个就是 7.8 µs，取 10 µs 保险。

如果不等就拉高，芯片可能还没把最后一个字节处理完，数据就错了。
这种时序要求在代码里出现十几次，**每次都手写一遍延时迟早会漏**，
所以封进宏里，只要写 `ADS_CS_H()` 就一定带延时。

`do { ... } while(0)` 是 C 语言的固定写法，作用是**让多条语句的宏在
`if` 后面也能正常工作**。比如：

```c
if (x) ADS_CS_H();      // 没有 do-while 的话，展开后 if 只管到第一句，后面那句无条件执行
else   ...              // 而且这里会编译报错
```

包一层 `do{}while(0)` 之后，整个宏就变成一条完整语句，怎么用都不会出问题。

#### SPI 命令码

```c
#define CMD_RDATAC    0x10      // 进连续读模式
#define CMD_SDATAC    0x11      // 退出连续读模式
#define CMD_RREG(a)   (0x20 | (a))    // 读寄存器 a
#define CMD_WREG(a)   (0x40 | (a))    // 写寄存器 a
```

这是手册 Table 15 定的。读写寄存器命令的**高 3 位是操作码，低 5 位是地址**：

```
RREG:  0 0 1 a a a a a      → 0x20 | 地址
WREG:  0 1 0 a a a a a      → 0x40 | 地址
```

所以 `CMD_WREG(0x01)` = `0x40 | 0x01` = `0x41`，意思是「写 01h 号寄存器」。

### 4.2 寄存器配置表 ads_cfg[11]

```c
static const uint8_t ads_cfg[11] = {
    0x02, 0xA0, 0x10, 0x00, 0x81, 0x23, 0x00, 0x00, 0x02, 0x05, 0x0C
};
```

ADS1292 的寄存器 `01h` 到 `0Bh` 是**连续的 11 个**，可以用一条 WREG 命令一次写完
（这就是 `ads_wreg(0x01, 11, ads_cfg)` 那一句）。数组下标 0 对应 01h。

逐个说：

| 下标 | 地址 | 名字 | 值 | 含义 |
|---|---|---|---|---|
| 0 | 01h | CONFIG1 | `0x02` | 采样率 |
| 1 | 02h | CONFIG2 | `0xA0` | 基准电压 |
| 2 | 03h | LOFF | `0x10` | 导联脱落检测（默认值） |
| 3 | 04h | CH1SET | `0x00` | 通道 1 增益和输入 |
| 4 | 05h | CH2SET | `0x81` | 关闭通道 2 |
| 5 | 06h | RLD_SENS | `0x23` | 右腿驱动 |
| 6 | 07h | LOFF_SENS | `0x00` | 关闭脱落检测 |
| 7 | 08h | LOFF_STAT | `0x00` | 时钟分频 |
| 8 | 09h | RESP1 | `0x02` | **固定值，见下** |
| 9 | 0Ah | RESP2 | `0x05` | RLD 参考源 |
| 10 | 0Bh | GPIO | `0x0C` | GPIO（默认值） |

#### 展开几个重要的

**CONFIG1 = 0x02**

```
bit:  7    6 5 4 3    2 1 0
     SINGLE_SHOT  保留   DR[2:0]
      0            000    010
```
`DR = 010` → 500 SPS。`SINGLE_SHOT = 0` → 连续转换模式（不用每次触发）。

为什么选 500 SPS？训练模型用的 MIT-BIH 数据是 360 Hz，
500 Hz 采回来在香橙派上重采样到 360 Hz 很方便，而且 500 是整数倍关系好处理。

**CONFIG2 = 0xA0**

```
bit:   7      6        5           4        3      2    1 0
      保留  保留  PDB_LOFF_COMP  PDB_REFBUF  VREF_4V  保留 INT_TEST TEST_FREQ
       1     0        1            0          0       0    0   0
```
- **bit7 必须写 1**（手册规定，写 0 芯片行为未定义）
- `PDB_REFBUF = 1` → 打开内部基准电压缓冲，输出 2.42 V。
  不打开的话你得从外面给 VREFP 供电，我们没有外部基准，所以必须开。
- `INT_TEST = 0` → 现在不用测试信号（测试模式下会被 `ads_enable_test_signal()` 改成 1）

**CH1SET = 0x00**

```
bit:  7    6 5 4       3 2 1 0
     PD1   GAIN[2:0]   MUX[3:0]
      0      000         0000
```
- `PD1 = 0` → 通道 1 上电（1 是关闭）
- `GAIN = 000` → **增益 6 倍**（这是 ADS1292 的默认，000 代表 6 不是 1，容易看错）
- `MUX = 0000` → 正常电极输入

增益 6 配 2.42 V 基准，输入范围是 ±2.42/6 = ±403 mV。心电信号只有 1~2 mV，
看起来浪费了动态范围，但电极上会叠加几百 mV 的**直流失调**（皮肤-电极半电池电位），
增益开太大会饱和。6 倍是稳妥选择。

**CH2SET = 0x81**

```
bit:  7    6 5 4       3 2 1 0
     PD2   GAIN[2:0]   MUX[3:0]
      1      000         0001
```
- `PD2 = 1` → **关闭通道 2**（我们只用一个导联，关掉省电、少噪声）
- `MUX = 0001` → 输入短接

注意：手册 p55 有个脚注说，关闭通道时**必须同时把 MUX 设成 001（输入短接）**，
只写 `PD2=1` 不够，浮空的输入会耦合噪声进来串扰到通道 1。

**RLD_SENS = 0x23**

```
bit:  7     6      5      4      3     2     1     0
     CHOP  PDB_RLD RLD_LOFF_SENS RLD2N RLD2P RLD1N RLD1P
      0  0    1       0        0     0     1     1
```
- `PDB_RLD = 1` → 打开右腿驱动
- `RLD1N = RLD1P = 1` → 从通道 1 的**正负两个电极**取共模电压

**RLD（右腿驱动）是干什么的？** 人体像一根天线，身上感应了几伏的 50 Hz 工频干扰。
RLD 把测到的共模干扰**反相后通过第三个电极注回人体**，主动抵消掉。
不开 RLD 的话，你采到的波形基本被 50 Hz 淹没，看不到心电。

**RESP1 = 0x02**

手册 p60 明确写着：**非 -R 型号（也就是 ADS1292 而不是 ADS1292R）必须写 02h**。
没有解释为什么，就是照做。写错了通道会工作不正常。

**RESP2 = 0x05**

```
bit:  7        6 5 4 3      2        1       0
   CALIB_ON     保留     RLDREF_INT  保留    保留
     0          000         1         0      1
```

等等，位定义我按手册再对一下：bit1 是 `RLDREF_INT`，`0` = RLD 参考用**外部**分压。

我们板子上做了外部电阻分压给 RLDREF，所以选外部（`0`）。bit0 必须写 1。
`0x05 = 0000 0101`：bit2=1、bit0=1，bit1=0（外部参考）。✅

### 4.3 环形缓冲的变量

```c
#define RB_SIZE       256

static volatile int32_t  rb_buf[RB_SIZE];   // 数据本体，256×4 = 1024 字节
static volatile uint16_t rb_head = 0;       // 写位置，只由中断改
static volatile uint16_t rb_tail = 0;       // 读位置，只由主循环改

static volatile uint32_t frame_ok   = 0;    // 正常帧计数
static volatile uint32_t frame_err  = 0;    // 帧同步错误计数
static volatile uint32_t rb_drop    = 0;    // 缓冲满了丢弃的次数
```

#### `volatile` 是什么意思

告诉编译器：**这个变量随时可能被别人改，每次用都要重新从内存读，不许优化。**

不加会出事。比如主循环这句：

```c
if (rb_tail != rb_head) { ... }
```

编译器一看：`rb_head` 在这个循环里从头到尾没被赋值过，那我读一次存到寄存器里
就行了呗，何必每次都去内存取？于是优化成只读一次。
结果中断把内存里的 `rb_head` 改了，主循环用的还是寄存器里的旧值，
**永远发现不了有新数据，程序死在空转上**。

加了 `volatile`，编译器就老老实实每次都去内存读。

**凡是「中断和主循环都会碰」的变量，必须加 `volatile`。**

#### 为什么只有 256

STM32F103**C8**T6 的 RAM 只有 **20 KB**。

`256 × 4 字节 = 1 KB`，占 5%，可以接受。

有人会想「那我开大点存 10 秒数据一次性发出去多好」——算一下：
`500 SPS × 10 秒 × 4 字节 = 20000 字节`，正好是**整个 RAM**，
连栈都没地方放，直接崩。

所以定位很清楚：**STM32 只负责采集和转发，不做缓存和计算。**
滤波、重采样到 360 Hz、切 10 秒窗口、模型推理，全部在香橙派上做。

256 个样本 = 512 ms，足够吸收串口偶尔的抖动。

### 4.4 微秒延时 dwt_init + delay_us

```c
static void dwt_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;   // 打开调试模块总开关
    DWT->CYCCNT = 0;                                  // 计数器清零
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;             // 启动周期计数器
}

static void delay_us(uint32_t us)
{
    uint32_t start = DWT->CYCCNT;
    uint32_t ticks = us * (SystemCoreClock / 1000000U);
    while ((DWT->CYCCNT - start) < ticks) { }
}
```

**DWT 是什么？** Data Watchpoint and Trace，Cortex-M3 内核自带的调试单元。
里面有个 `CYCCNT` 寄存器，**每过一个 CPU 时钟周期就 +1**，是个纯硬件计数器。

72 MHz 主频下，1 µs = 72 个周期。所以 `delay_us(10)` 就是等 720 个周期。

#### 为什么不用 HAL_Delay？

两个原因：

1. **精度不够。** `HAL_Delay` 最小单位是 **1 毫秒**，而我们要等的是 **7.8 微秒**。
   用 `HAL_Delay(1)` 等价于等了 128 倍那么久，初始化会慢得离谱，
   而且 CS 拉高这个动作在中断里每 2 ms 就要做一次，等 1 ms 直接把时序毁了。

2. **中断里不能用。** `HAL_Delay` 靠 `HAL_GetTick()` 计时，而我们在第二节说过，
   EXTI0 优先级 3 高于 SysTick 的 15，**中断里 tick 是冻结的**。
   `HAL_Delay` 的循环唯一的退出条件就是 tick 前进，没有任何兜底，
   所以会**永远卡死**。（这一条跟 SPI 不同——SPI 是靠硬件标志退出的，
   在中断里其实能正常跑完，只是丢了超时保护。详见第二节。）

DWT 的 `CYCCNT` 是硬件自增的，跟中断优先级完全无关，所以在中断里也能安全用。

#### 那个减法为什么不怕溢出

`CYCCNT` 是 32 位，72 MHz 下大约 **59.6 秒**溢出一次回到 0。

```c
while ((DWT->CYCCNT - start) < ticks)
```

假设 `start = 0xFFFFFF00`，现在 `CYCCNT` 已经绕回 `0x00000010`：
无符号减法 `0x00000010 - 0xFFFFFF00 = 0x00000110 = 272`，正好是真实经过的周期数。

**无符号整数的减法自带取模运算，溢出会自动算对**，这是嵌入式里的常用技巧。

### 4.5 串口输出三兄弟

#### uart_puts —— 发一个字符串

```c
static void uart_puts(const char *s)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)s, (uint16_t)strlen(s), HAL_MAX_DELAY);
}
```

`HAL_MAX_DELAY` = 永不超时，一直等到发完（阻塞式）。在主循环里这样用没问题。

#### uart_printf —— 带格式化，只在初始化时用

```c
static void uart_printf(const char *fmt, ...)
{
    char buf[128];
    va_list ap;
    va_start(ap, fmt);
    int n = vsnprintf(buf, sizeof(buf), fmt, ap);
    va_end(ap);
    if (n > 0) HAL_UART_Transmit(&huart1, (uint8_t *)buf, (uint16_t)n, HAL_MAX_DELAY);
}
```

`...` 是**可变参数**，让你能像 `printf` 那样写 `uart_printf("ID = 0x%02X\r\n", id)`。

`va_list` / `va_start` / `va_end` 是 C 标准库处理可变参数的三件套：
`va_start` 定位到第一个可变参数，`vsnprintf` 按格式串把它们转成文本填进 `buf`，
`va_end` 收尾。

`vsnprintf` 的 `n` 是「**如果缓冲区够大，本来该写多少字符**」，
所以用 `buf` 里实际内容的长度发送就行（这里 128 字节足够，不会截断）。

**这个函数比较慢**（`vsnprintf` 要解析格式串），所以只用在初始化打印，
不用在每 2 ms 一次的数据输出上。

#### print_i32 —— 快速发一个整数

```c
static void print_i32(int32_t v)
{
    char     buf[13];
    uint8_t  i = sizeof(buf);   // i = 13，从数组末尾往前填
    uint32_t u;

    buf[--i] = '\n';            // buf[12] = '\n'
    buf[--i] = '\r';            // buf[11] = '\r'

    u = (v < 0) ? (uint32_t)(-(int64_t)v) : (uint32_t)v;   // 取绝对值
    if (u == 0) { buf[--i] = '0'; }
    else        { while (u > 0) { buf[--i] = (char)('0' + (u % 10)); u /= 10; } }
    if (v < 0)  { buf[--i] = '-'; }

    HAL_UART_Transmit(&huart1, (uint8_t *)&buf[i],
                      (uint16_t)(sizeof(buf) - i), HAL_MAX_DELAY);
}
```

**为什么倒着填？** 因为把数字转成十进制文本，只能**从个位开始**取
（`u % 10` 拿到个位，`u /= 10` 去掉个位）。个位是最后一个字符，
所以从数组尾巴往前写，写完正好是正序，不用再翻转一遍。

举例 `v = -20960`：

```
初始    i=13
'\n'    i=12  buf[12]='\n'
'\r'    i=11  buf[11]='\r'
u=20960 → 0   i=10  buf[10]='0'
        → 6   i=9   buf[9] ='6'
        → 9   i=8   buf[8] ='9'
        → 0   i=7   buf[7] ='0'
        → 2   i=6   buf[6] ='2'
负号          i=5   buf[5] ='-'

发送 &buf[5]，长度 13-5=8   →   "-20960\r\n"  ✅
```

**为什么 `-(int64_t)v`？** 因为 `int32_t` 的最小值是 `-2147483648`，
它的绝对值 `2147483648` **超出了 int32_t 的表示范围**，直接 `-v` 会溢出（未定义行为）。
先转成 64 位再取负就安全了。虽然我们的数据只有 24 位不会碰到这个边界，
但写对了不吃亏。

`buf[13]` 够不够？最长的情况是 `-2147483648\r\n` = 11+2 = 13，正好。

### 4.6 spi_xfer：为什么偏要自己写

```c
static uint8_t spi_xfer(uint8_t tx)
{
    while ((SPI1->SR & SPI_SR_TXE) == 0U) { }      // 等发送缓冲空
    *(volatile uint8_t *)&SPI1->DR = tx;           // 写入要发的字节
    while ((SPI1->SR & SPI_SR_RXNE) == 0U) { }     // 等接收缓冲有数
    return *(volatile uint8_t *)&SPI1->DR;         // 读出收到的字节
}
```

#### SPI 是「同时收发」的

SPI 是全双工的移位寄存器结构：你往外推 8 位的同时，对方的 8 位也被推进来。
**发一个字节 = 收一个字节，这两件事是同一次操作。**

所以读数据的时候，虽然我们不需要发任何东西，也得发个 `0x00` 出去
「把时钟转起来」，才能把对方的数据换进来。这就是 ISR 里 `spi_xfer(0x00)` 的含义。

#### 两个标志位

- `TXE`（Transmit buffer Empty）= 1 表示发送缓冲空了，可以写新数据
- `RXNE`（Receive buffer Not Empty）= 1 表示收到数据了，可以读

#### 那个奇怪的强制转换

```c
*(volatile uint8_t *)&SPI1->DR = tx;
```

`SPI1->DR` 本身是 16 位寄存器。如果直接写 `SPI1->DR = tx`，编译器会生成
**16 位写指令**（`strh`），STM32 的 SPI 外设看到 16 位访问会认为你要发 16 位数据，
**多发一个字节出去**，时序就全乱了。

强制转成 `uint8_t*` 再解引用，编译器就生成**8 位写指令**（`strb`），
外设才知道这是 8 位传输。读的时候同理。

这是 STM32 SPI 的经典坑，ST 官方例程里也是这么写的。

#### 为什么不用 HAL_SPI_TransmitReceive

第二节详细讲过了，这里总结成表：

| | HAL_SPI_TransmitReceive | spi_xfer |
|---|---|---|
| 中断里能读到数据吗 | ✅ 能（靠硬件标志退出，不依赖 tick） | ✅ 能 |
| 超时保护 | ❌ 中断里失效，故障时无限等待 | 本来就没有，行为一致 |
| `__HAL_LOCK` 重入风险 | ⚠️ 主循环也用 SPI 时会返回 `HAL_BUSY` 静默丢帧 | ❌ 无锁 |
| 每字节额外开销 | 有（状态机、锁、CRC 判断、回调） | 无 |
| 代码量 | HAL 内部约 200 行 | 5 行 |

**所以不是"HAL 不能用"，是"HAL 在这个位置会悄悄丢掉两层保护"。**
选自己写的版本是为了可靠性和速度，不是因为 HAL 跑不起来。

**代价：** 因为绕过了 HAL，`HAL_SPI_Init()` 不会帮我们打开 SPI 外设。
所以 `main()` 里必须补一句（见 4.12）：

```c
__HAL_SPI_ENABLE(&hspi1);
```

`HAL_SPI_Init()` 只配置了寄存器（时钟分频、模式、位序），**SPE 使能位是留到
第一次调用传输函数时才置的**。我们不调那些函数，就得自己置，
否则 `TXE` 永远等不到，程序卡在第一个 `while` 上。

### 4.7 三个 ADS 操作函数（SPI 协议长什么样）

#### ads_cmd —— 发单字节命令

```c
static void ads_cmd(uint8_t op)
{
    ADS_CS_L();          // 片选拉低，开始一次通信
    spi_xfer(op);        // 发 1 个字节
    ADS_CS_H();          // 片选拉高（宏里自带 10µs 延时）
    delay_us(10);        // 命令之间也要间隔 4 tCLK
}
```

用于 `SDATAC` / `RDATAC` 这种不带参数的命令。

#### ads_wreg —— 写寄存器

```c
static void ads_wreg(uint8_t addr, uint8_t n, const uint8_t *in)
{
    ADS_CS_L();
    spi_xfer(CMD_WREG(addr));      // 第1字节：0x40 | 起始地址
    spi_xfer((uint8_t)(n - 1));    // 第2字节：要写几个，减1
    for (i = 0; i < n; i++) spi_xfer(in[i]);   // 后面依次是数据
    ADS_CS_H();
    delay_us(10);
}
```

时序图（写 11 个寄存器，从 01h 开始）：

```
CS   ──┐                                                    ┌──
       └────────────────────────────────────────────────────┘
DIN     0x41   0x0A   0x02  0xA0  0x10 ...................  0x0C
        ↑      ↑      ↑                                     ↑
      WREG+01h  11-1  第1个数据(01h)                    第11个数据(0Bh)
```

**为什么第 2 个字节要减 1？** 手册就是这么定的：`(n-1)` 表示数量。
写 1 个寄存器发 `0x00`，写 11 个发 `0x0A`。忘了减 1 是常见 bug，
会导致多写一个寄存器，把 0Ch 也覆盖掉。

#### ads_rreg —— 读寄存器

```c
static void ads_rreg(uint8_t addr, uint8_t n, uint8_t *out)
{
    ADS_CS_L();
    spi_xfer(CMD_RREG(addr));      // 0x20 | 地址
    spi_xfer((uint8_t)(n - 1));
    for (i = 0; i < n; i++) out[i] = spi_xfer(0x00);   // 发0x00换数据回来
    ADS_CS_H();
    delay_us(10);
}
```

跟写的区别只在于：命令码是 `0x20` 打头，后面的字节**发 `0x00` 收数据**。

### 4.8 中断回调（核心）

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    uint8_t  f[9];
    uint8_t  i;
    int32_t  v;
    uint16_t next;

    if (GPIO_Pin != ADS_DRDY_PIN) { return; }

    ADS_CS_L();
    for (i = 0; i < 9; i++) { f[i] = spi_xfer(0x00); }
    ADS_CS_H();

    if (((f[0] & 0xF0U) != 0xC0U) || (f[2] != 0x00U))
    {
        frame_err++;
        return;
    }
    frame_ok++;

    v = ((int32_t)f[3] << 16) | ((int32_t)f[4] << 8) | (int32_t)f[5];
    if ((v & 0x00800000) != 0) { v |= (int32_t)0xFF000000; }

    next = (uint16_t)((rb_head + 1U) % RB_SIZE);
    if (next == rb_tail) { rb_drop++; return; }
    rb_buf[rb_head] = v;
    rb_head = next;
}
```

#### 这个函数是怎么被调用的

你在 CubeMX 里勾了 EXTI0 的 NVIC 使能，它生成了这条链：

```
DRDY 引脚下降沿
    ↓ 硬件
EXTI0_IRQHandler()              ← 在 stm32f1xx_it.c，CubeMX 生成，别改
    ↓
HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)   ← HAL 库里，清中断标志
    ↓
HAL_GPIO_EXTI_Callback(GPIO_PIN_0)     ← 弱函数，我们在 main.c 里重写它
```

HAL 库里 `HAL_GPIO_EXTI_Callback` 被声明成 `__weak`（弱符号），
意思是「这是个空的默认实现，你要是自己定义一个同名的，链接器就用你的」。
所以我们在 main.c 里写一个同名函数，**不需要任何注册动作**，自动就被调用了。

#### 第一句：判断是哪个引脚

```c
if (GPIO_Pin != ADS_DRDY_PIN) { return; }
```

**所有** EXTI 中断最后都汇集到这一个回调函数。如果你以后再加一个按键中断，
也会跑进这里。所以必须先看参数判断是谁来的，不是我们关心的就直接返回。

现在只有一个中断源，这句看起来多余，但加上是好习惯。

#### 读一帧 9 个字节

ADS1292 在 RDATAC 模式下，每次数据就绪会准备好 **72 位（9 字节）**：

```
字节:   0    1    2  |  3    4    5  |  6    7    8
      └─ STATUS ─┘   └── CH1 ────┘   └── CH2 ────┘
        24 位          24 位            24 位
```

- **STATUS**：状态字，格式固定（下面说）
- **CH1**：通道 1 的转换结果，24 位二进制补码，高位在前
- **CH2**：通道 2，我们关掉了，值是噪声，不用管

因为在 RDATAC 模式，**不需要先发 RDATA 命令**，拉低 CS 直接读 9 个字节就行。

#### 帧同步校验

```c
if (((f[0] & 0xF0U) != 0xC0U) || (f[2] != 0x00U))
```

STATUS 这 24 位的格式是（手册 p42）：

```
位:  23 22 21 20 | 19 18 17 16 15 | 14 13 | 12 ......... 0
      1  1  0  0 | LOFF_STAT[4:0] |GPIO[1:0]|  13 个 0
     └─ 固定 ─┘

拆成字节:
  f[0] = 1100 + LOFF_STAT[4:1]     → 高 4 位永远是 1100 = 0xC
  f[1] = LOFF_STAT[0] + GPIO[1:0] + 5个0
  f[2] = 全 0                       → 永远是 0x00
```

所以「`f[0]` 的高 4 位是 `0xC`」和「`f[2]` 等于 `0x00`」这两个条件
**在数据正确的时候必然成立**。

如果不成立，说明 SPI 读**错位**了（比如某次通信丢了一个时钟沿，
从此以后每次都少读一位，数据全乱）。这时候我们不能把垃圾数据放进缓冲，
计数一下直接丢掉。

**`frame_err` 一直是 0 = 通信健康。** 如果它在涨，去查 SPI 接线、CS 时序、
或者把 SPI 速度降一档。

#### 拼接 24 位 + 符号扩展（这段最容易看不懂）

```c
v = ((int32_t)f[3] << 16) | ((int32_t)f[4] << 8) | (int32_t)f[5];
if ((v & 0x00800000) != 0) { v |= (int32_t)0xFF000000; }
```

**第一步：拼接。** 芯片是高位在前发的，所以：

```
f[3] = 0xFF    →  左移16位  →  0x00FF0000
f[4] = 0xAE    →  左移8位   →  0x0000AE00
f[5] = 0x30    →  不移      →  0x00000030
                   按位或    →  0x00FFAE30
```

**第二步：符号扩展。** 这是关键。

ADS1292 输出的是 **24 位二进制补码**，取值范围 `-8388608 ~ +8388607`。
但我们把它放进了 32 位的 `int32_t` 变量里，高 8 位是 0。

对于正数没问题。但对于负数就错了：

```
24位补码 -1  =  0xFFFFFF
放进32位后   =  0x00FFFFFF  =  +16777215   ← 变成了大正数！错了
正确应该是    =  0xFFFFFFFF  =  -1          ← 高8位要补满1
```

**判断正负看第 24 位（最高位）**，也就是 `0x00800000` 这个掩码：

```
0x00800000 = 0000 0000 1000 0000 0000 0000 0000 0000
                       ↑ 第23位（从0数），24位数的符号位
```

如果这一位是 1（负数），就把高 8 位全部填 1：

```c
v |= 0xFF000000;
```

```
0x00FFFFFF  |  0xFF000000  =  0xFFFFFFFF  =  -1   ✅
```

如果是正数（符号位为 0），高 8 位保持 0 就是对的，不用动。

**忘了这一步的后果：** 波形一半正常，另一半在 -1 mV 以下的部分会突然
跳到 +8388607 附近，画出来是满屏尖刺。这是新手写 24 位 ADC 驱动最常见的错误。

#### 入队

```c
next = (uint16_t)((rb_head + 1U) % RB_SIZE);
if (next == rb_tail) { rb_drop++; return; }   // 满了
rb_buf[rb_head] = v;
rb_head = next;
```

详见下一节。

#### 注意 `f[9]` 是局部变量

它在**栈**上。每次进中断分配 9 字节，出中断就释放。这是对的：

- 不会跟主循环冲突（主循环看不到它）
- 不占用全局 RAM
- 中断不会自己嵌套自己，所以不存在两个实例同时用一个数组的问题

#### 整个中断耗时

9 字节 × 8 位 ÷ 562500 Hz = **128 µs**（SPI 传输占绝大部分）
加上 CS 前后两个 10 µs 延时和几十条指令，大约 **150 µs**。

中断周期 2000 µs，**占用率 7.5%**，CPU 剩下 92.5% 的时间给主循环发串口，很宽裕。

### 4.9 环形缓冲到底怎么转

这是整个程序里唯一有点绕的数据结构，单独讲。

#### 它解决什么问题

中断每 2 ms 产生一个数据，主循环每 700 µs 消费一个。速度不完全同步，
中间需要一个「缓冲池」。用普通数组不行（不知道写到哪了），
用队列又要移动数据（太慢）。**环形缓冲 = 首尾相连的数组 + 两个指针**。

#### 两个指针

```
rb_head  写指针：中断往这里放新数据，放完 +1
rb_tail  读指针：主循环从这里取数据，取完 +1
```

**规则：`head == tail` 表示空，`(head+1)%N == tail` 表示满。**

#### 图解

初始状态，两个指针重合，缓冲为空：

```
下标  0    1    2    3    4    5   ...  255
     ┌────┬────┬────┬────┬────┬────┬───┬────┐
     │    │    │    │    │    │    │   │    │
     └────┴────┴────┴────┴────┴────┴───┴────┘
       ↑
    head=0
    tail=0        head == tail  →  空
```

中断放了 3 个数据（head 前进到 3）：

```
     ┌────┬────┬────┬────┬────┬────┬───┬────┐
     │ A  │ B  │ C  │    │    │    │   │    │
     └────┴────┴────┴────┴────┴────┴───┴────┘
       ↑              ↑
    tail=0         head=3      head != tail  →  有 3 个数据
```

主循环取走 A（tail 前进到 1）：

```
     ┌────┬────┬────┬────┬────┬────┬───┬────┐
     │ ×  │ B  │ C  │    │    │    │   │    │
     └────┴────┴────┴────┴────┴────┴───┴────┘
            ↑         ↑
         tail=1    head=3      还剩 2 个
```

写到末尾时，`% RB_SIZE` 让指针**绕回 0**，这就是「环形」的由来：

```
head=255 时：next = (255+1) % 256 = 0    ← 绕回开头
```

```
     ┌────┬────┬────┬────┬────┬────┬───┬────┐
     │ G  │    │    │ D  │ E  │ F  │...│    │
     └────┴────┴────┴────┴────┴────┴───┴────┘
            ↑    head 绕回来了      ↑
         head=1                  tail=3
```

#### 为什么「满」的判断是 `(head+1)%N == tail` 而不是 `head == tail`

因为 `head == tail` 已经被「空」占用了，**空和满没法区分**。
牺牲一个格子不用，就能靠 `head+1 == tail` 区分出满：

```
     ┌────┬────┬────┬────┬────┬────┬───┬────┐
     │ X  │ X  │ X  │    │ X  │ X  │ X │ X  │
     └────┴────┴────┴────┴────┴────┴───┴────┘
                  ↑    ↑
              head=3  tail=4     (3+1)%256 == 4  →  满
                                  下标3这个格子永远不用
```

所以 256 的缓冲实际最多存 255 个。无所谓。

#### 为什么不需要关中断保护

一般来说，中断和主循环共享变量是要加临界区（关中断）的。这里不用，因为：

| | 写者 | 读者 |
|---|---|---|
| `rb_head` | **只有中断** | 主循环 |
| `rb_tail` | **只有主循环** | 中断 |

**每个变量只有一个写者**，这叫「单生产者单消费者」模型。

再加上 `uint16_t` 在 Cortex-M3 上的读写是**单条指令、原子的**
（不会读到一半被中断打断，读出半新半旧的值），所以天然安全。

如果换成 `uint32_t` 的 64 位变量，或者有两个中断都往里写，就必须加保护了。

#### 满了怎么办

```c
if (next == rb_tail) { rb_drop++; return; }   // 丢弃这个新样本
```

**丢新的还是丢旧的？** 这里选择丢新的（直接 return，不覆盖）。
另一种做法是覆盖最旧的（`rb_tail` 也前进一格）。

对心电来说两者都会破坏数据连续性，所以关键不是选哪种，
而是**保证 `rb_drop` 一直是 0**。它一旦开始涨，说明串口跟不上采样，
必须提高波特率或者改二进制传输（见第九节）。

### 4.10 测试信号 ads_enable_test_signal

```c
static void ads_enable_test_signal(void)
{
    uint8_t v;

    v = 0xA3;      // CONFIG2: bit7=1, PDB_REFBUF=1, INT_TEST=1, TEST_FREQ=1
    ads_wreg(REG_CONFIG2, 1, &v);

    v = 0x05;      // CH1SET: 增益6, MUX=0101 选测试信号
    ads_wreg(REG_CH1SET, 1, &v);

    uart_puts("*** 测试信号模式：应输出 ±20960 的 1Hz 方波 ***\r\n");
}
```

它在 `ads_wreg(REG_CONFIG1, 11, ads_cfg)` **之后**执行，
把刚写进去的 CONFIG2 和 CH1SET 这两个字节**再改一遍**。

- `CONFIG2` 从 `0xA0` 改成 `0xA3`：`INT_TEST=1` 打开内部测试信号发生器，
  `TEST_FREQ=1` 选 1 Hz 方波（`0` 是直流）
- `CH1SET` 从 `0x00` 改成 `0x05`：`MUX=0101` 把通道 1 的输入
  **从电极切换到内部测试信号**

#### 期望值怎么算出来的

手册规定测试信号幅度是 `±(VREFP - VREFN) / 2400`：

```
±2.42 V / 2400 = ±1.0083 mV        （这是加在输入端的电压）
```

经过 6 倍增益后送进 ADC，转换成原始码：

```
LSB = 2 × VREF / 增益 / 2^24
    = 2 × 2.42 / 6 / 16777216
    = 48.081 nV

原始码 = 1.0083 mV / 48.081 nV ≈ 20970
```

所以串口应该看到数值在 **+20960 和 -20960 之间每秒跳变一次**
（1 Hz 方波，500 SPS 采样，所以每 250 个点跳一次）。

看到这个 = **芯片、SPI、数据解析、串口全部正常**，
接下来只需要处理模拟前端（电极、导线、RLD）。

### 4.11 初始化 ads1292_init 的 11 步

这个函数是全篇最长的，但逻辑是一条直线。所有的延时数值都来自手册，
不是随便写的。先给一张速查表：

| 步 | 做什么 | 等多久 | 手册依据 |
|---|---|---|---|
| 0 | 关 EXTI0 中断 | — | 避免配置期间假中断 |
| 1 | RESET/START 拉低，CS 拉高 | — | 10.1 上电所有数字输入为低 |
| 2 | 等上电复位完成 | 100 ms | tPOR = 2¹² tMOD = 32 ms |
| 3 | RESET 拉高退出掉电 | 20 ms | 掉电→就绪 10 ms |
| 4 | 发一个复位脉冲 | 100 µs + 50 µs | tRST > 7.8 µs；复位后 18 tCLK |
| 5 | 发 SDATAC | 10 µs | Table 15 脚注1 |
| 5.5 | 读 ID 校验 SPI | — | Table 17，bit4 固定为 1 |
| 6 | 写 11 个寄存器 | 10 ms | 写 CONFIG1 会复位数字滤波器 |
| 7 | 回读校验 | — | 确认配置真的生效了 |
| 8 | 等基准电压建立 | 1000 ms | VCAP1 到 1% 需 500 ms |
| 9 | START 拉高 + 发 RDATAC | — | 8.5.1.9 |
| 10 | 等数字滤波器建立 | 20 ms | 8.3.5，3 tDR = 6 ms |
| 11 | 清标志，开中断 | — | 起点干净 |

#### 时间常数从哪来

内部时钟 `fCLK = 512 kHz`（CLK_DIV=0），所以：

```
tCLK = 1 / 512000        = 1.953 µs      一个时钟周期
tMOD = 4 × tCLK          = 7.8125 µs     调制器周期
tDR  = 1 / 500           = 2 ms          数据输出周期（500 SPS）
```

手册里的时间都用这三个量表示，比如「tPOR = 2¹² tMOD」= 4096 × 7.8125 µs = 32 ms。

#### 第 0 步：先关中断（★ 容易漏）

```c
HAL_NVIC_DisableIRQ(EXTI0_IRQn);
```

**为什么必须关？** CubeMX 生成的 `MX_GPIO_Init()` 里有这两句：

```c
HAL_NVIC_SetPriority(EXTI0_IRQn, 3, 0);
HAL_NVIC_EnableIRQ(EXTI0_IRQn);           // ← 中断在这里就开了
```

而 `MX_GPIO_Init()` 在 `main()` 里比我们的初始化**早执行**。

也就是说，从 `MX_GPIO_Init()` 返回的那一刻起，DRDY 引脚只要有下降沿就会进中断。
而初始化过程中我们要复位芯片、写寄存器，**DRDY 会乱跳**。

如果不关：中断在 `ads_wreg()` 发到一半的时候插进来，
拉低 CS 读 9 个字节，**把正在进行的写寄存器操作彻底冲掉**。
结果就是配置写不进去，而且现象很诡异（时好时坏，跟时序赛跑）。

#### 第 1~2 步：上电初始电平

```c
ADS_RST_L();                                              // PWDN/RESET = 0
ADS_STARTP_L();                                           // START = 0
HAL_GPIO_WritePin(ADS_CS_PORT, ADS_CS_PIN, GPIO_PIN_SET); // CS = 1（不选中）
HAL_Delay(100);
```

手册 10.1 要求：**上电瞬间所有数字输入引脚必须是低电平**，
不然可能触发芯片内部的闩锁保护，或者进入未定义状态。

（这也是你板子上 PWDN/RESET 引脚接下拉电阻的原因 —— 在 STM32 还没跑起来、
GPIO 还是浮空输入的那几十毫秒里，靠电阻保证它是低的。）

CS 是唯一例外，高电平表示「不选中」，是空闲状态。

`HAL_Delay(100)` 等 tPOR（32 ms）过去，取 100 ms 是留裕量。

#### 第 3 步：退出掉电

```c
ADS_RST_H();
HAL_Delay(20);
```

`PWDN/RESET` 这个引脚是**复用**的：

- 一直拉低超过 `2^9 × tMOD = 4 ms` → 进入**掉电模式**
- 短暂拉低（微秒级）再拉高 → 触发**复位**

第 2 步等了 100 ms，芯片已经进掉电了。拉高唤醒，手册 p9 说
掉电→就绪需要 10 ms，等 20 ms。

#### 第 4 步：复位脉冲（★ 注意是靠跳变触发）

```c
ADS_RST_L();
delay_us(100);       // 脉冲宽度
ADS_RST_H();
delay_us(50);        // 复位后的恢复时间
```

**手册 8.5.1.8：复位是靠「高→低」这个跳变触发的，不是低电平本身。**

所以宽度选 100 µs：

```
下限：tRST > 2 tCLK = 3.9 µs        （太短芯片检测不到）
上限：< 2^9 tMOD = 4 ms             （太长会进掉电，就不是复位了）
100 µs 在中间，很安全
```

拉高后再等 50 µs：手册要求复位后 18 tCLK = 35 µs 内不能发命令。

**这一步为什么不能省？** 上一步的掉电唤醒不保证寄存器回到默认值。
显式复位一次，让芯片处于确定的初始状态，后面的配置才可靠。

#### 第 5 步：SDATAC（★★★ 最关键的一句）

```c
ads_cmd(CMD_SDATAC);
```

回到第二节的概念 2：**芯片上电默认在 RDATAC（连续读）模式，
在这个模式下 RREG 和 WREG 命令会被完全忽略。**

不发这一句，后面的：
- 读 ID → 读回来是 ADC 数据，不是 ID，校验必然失败
- 写 11 个寄存器 → 一个都写不进去，芯片还是默认配置

**而且芯片不会报错**，你只会看到一堆莫名其妙的数。
这是 ADS1292 驱动的头号坑。

#### 第 5.5 步：读 ID 校验通路

```c
ads_rreg(REG_ID, 1, &id);
uart_printf("ID  = 0x%02X  ", id);
if ((id & 0x10U) == 0U)
{
    uart_puts("[FAIL] SPI 不通\r\n");
    return -1;
}
```

手册 Table 17 规定 ID 寄存器（00h）的 **bit4 恒为 1**。
ADS1292 完整的 ID 值是 `0x53`（`0101 0011`，bit4 = 1 ✅）。

这一步的价值：**把「SPI 硬件不通」和「配置写错了」两类问题分开。**

- 读出 `0x00` 或 `0xFF` → 线没接对、SPI 没使能、CS 不对、芯片没供电
- 读出 `0x53` → 硬件通路完全正常，后面再出问题就是软件配置的事

先确认这个，能省掉大量瞎猜时间。

#### 第 6 步：写配置

```c
ads_wreg(REG_CONFIG1, 11, ads_cfg);
HAL_Delay(10);
```

一条命令写完 11 个寄存器（详见 4.2 和 4.7）。

后面等 10 ms 是因为：**写 CONFIG1、RESP1、RESP2 这三个寄存器会
自动复位芯片内部的数字滤波器**，需要时间重新稳定。

#### 第 7 步：回读校验

```c
ads_rreg(REG_CONFIG1, 11, rb);
uart_puts("REG = ");
for (i = 0; i < 11; i++) { uart_printf("%02X ", rb[i]); }
for (i = 0; i < 11; i++)
{
    if (rb[i] != ads_cfg[i])
    {
        uart_printf("\r\n[FAIL] 寄存器 0x%02X: 写 0x%02X 读回 0x%02X\r\n",
                    i + 1, ads_cfg[i], rb[i]);
        return -2;
    }
}
```

**把刚写进去的 11 个字节读回来，逐个对比。**

这是唯一能确认「配置真的生效了」的手段。
不做这一步的话，如果 SDATAC 漏了、或者 SPI 时序有问题导致写入失败，
你要一直到看波形不对的时候才发现，而那时候已经分不清是配置问题还是电极问题了。

不一致时打印**哪个寄存器、写的什么、读回什么**，直接定位问题。

（`i + 1` 是因为数组下标 0 对应寄存器地址 01h。）

#### 第 8 步：等基准建立（1 秒，看着久但必须等）

```c
uart_puts("等待基准建立 (1s) ...\r\n");
HAL_Delay(1000);
```

手册 p9 给的建立时间：

| 电压 | 精度 | 需要时间 | 取决于 |
|---|---|---|---|
| VREFP | 0.2% | 100 ms | 外接 10 µF |
| VCAP1 | 1% | 500 ms | 外接 1 µF |

VCAP1 是芯片内部模拟电源的滤波电容，它建立最慢。手册的参考流程
（Figure 44）直接等 1 秒，我们照做。

**不等的后果：** 前几百毫秒的数据是漂移的，基线会缓慢爬升。
反正只在开机时等一次，不影响后面。

#### 第 9 步：启动转换

```c
ADS_STARTP_H();          // START 拉高
ads_cmd(CMD_RDATAC);     // 进连续读模式
```

**顺序很重要。** 手册 8.5.1.9：**START 为低电平时，芯片根本不进行转换，
也就不会产生 DRDY。**

所以如果你烧完程序发现串口卡在「初始化完成」不动、一个数据都没有，
**第一个要查的就是 PB0（START）是不是 3.3 V**。

`RDATAC` 让芯片进入连续读模式，之后每次 DRDY 后直接读 9 字节就行，
不用每次都发 RDATA 命令。

#### 第 10 步：等滤波器建立

```c
HAL_Delay(20);
```

手册 8.3.5：ΔΣ 调制器后面跟的是 SINC 数字滤波器，
它是个 FIR 滤波器，输入发生阶跃后要 **3 个数据周期**才能完全建立。

`3 × tDR = 3 × 2 ms = 6 ms`，等 20 ms 留裕量。
这期间的前几个数据是无效的，等过去了再开中断就不会采到它们。

#### 第 11 步：清干净再开中断

```c
rb_head = 0;
rb_tail = 0;
__HAL_GPIO_EXTI_CLEAR_IT(ADS_DRDY_PIN);   // 清 EXTI 挂起标志
NVIC_ClearPendingIRQ(EXTI0_IRQn);          // 清 NVIC 挂起标志
HAL_NVIC_EnableIRQ(EXTI0_IRQn);            // 真正开中断
```

前面配置的十几个步骤里，DRDY 引脚有过很多次跳变。虽然中断被 `Disable` 了
**不会执行**，但 EXTI 和 NVIC 的**挂起标志位还是会被硬件置起来**。

如果直接 `EnableIRQ`，这些积攒的挂起标志会立刻触发一次（或多次）中断，
去读一帧根本不存在的数据。

所以要**清两层标志**：

- `__HAL_GPIO_EXTI_CLEAR_IT` 清 EXTI 外设的 `PR` 寄存器
- `NVIC_ClearPendingIRQ` 清 NVIC 控制器的挂起位

两个都清了，再开中断，第一个进来的就是真正的新数据。

缓冲指针也归零，保证从空开始。

### 4.12 main 函数

#### USER CODE 2 —— 初始化

```c
dwt_init();
```
打开 DWT 周期计数器，`delay_us` 才能工作。**必须在任何 `delay_us` 之前调用**，
否则 `CYCCNT` 不动，`delay_us` 会死循环。

```c
__HAL_SPI_ENABLE(&hspi1);
```
见 4.6 —— `HAL_SPI_Init()` 不置 SPE 位，我们绕过 HAL 就得自己开。
**漏了这句程序会卡死在 `spi_xfer` 的第一个 `while` 上。**

```c
uart_printf("SystemCoreClock = %lu Hz\r\n", (unsigned long)SystemCoreClock);
if (SystemCoreClock != 72000000UL)
{
    uart_puts("[WARN] 时钟不是 72MHz，delay_us 会不准（HSE 可能没起振）\r\n");
}
```

**为什么要检查时钟？** `delay_us` 的换算 `us × (SystemCoreClock/1000000)`
完全依赖主频。如果外部晶振没起振，HAL 会自动退回内部 8 MHz RC 振荡器，
主频变成 8 MHz，**所有微秒延时都会短 9 倍**，SPI 时序全部违规，
现象是「时好时坏」，极难排查。

打印出来一眼就能看到。（顺便也验证了你的 8 MHz 晶振焊接和负载电容是对的。）

```c
while (ads1292_init() != 0)
{
    uart_puts("初始化失败，3 秒后重试...\r\n\r\n");
    HAL_Delay(3000);
}
```

初始化失败就每 3 秒重试一次，不往下走。这样调试时可以一边看串口输出、
一边拿表笔量电压/重新插拔，不用反复按复位键。

#### USER CODE 3 —— 主循环

```c
while (1)
{
    if (rb_tail != rb_head)
    {
        int32_t v = rb_buf[rb_tail];
        rb_tail = (uint16_t)((rb_tail + 1U) % RB_SIZE);
        print_i32(v);
    }
}
```

就三件事：

1. `rb_tail != rb_head` → 缓冲里有数据吗
2. 取出来，读指针 +1（绕回）
3. 转成文本发串口

**注意顺序：先取数据 `rb_buf[rb_tail]`，再移动 `rb_tail`。**
反过来的话，中断可能在这个空档往刚"释放"的格子里写新数据，把你还没读的值覆盖掉。

主循环里**没有任何延时**，全速空转。这是对的：
- 有数据就立刻发，延迟最小
- 没数据就空转，反正也没别的事干
- 采样时序由 DRDY 中断保证，跟主循环快慢无关

## 五、时间预算：这套能不能跑得动

| 项目 | 数值 | 计算 |
|---|---|---|
| 采样周期 | **2000 µs** | 1 / 500 SPS |
| SPI 时钟 | 562.5 kHz | 72 MHz / 128 |
| 中断读一帧 | **~150 µs** | 9 字节 × 8 位 / 562500 + 两个 10µs 延时 |
| 中断占用率 | **7.5%** | 150 / 2000 |
| 串口发一行 | **~700 µs** | 8 字符 × 10 位 / 115200 |
| 串口占用率 | **35%** | 700 / 2000 |
| **总占用** | **~43%** | 还有一半余量 |

串口带宽核算：

```
最长一行 "-8388608\r\n" = 10 字符 = 100 位（8N1，每字符 10 位）
500 行/秒 × 100 位 = 50000 bps
115200 bps 的容量 → 用了 43%           ✅ 够
```

测试信号模式下每行只有 8 字符，更宽裕。

**什么时候会不够？**
- 提高到 1000 SPS → 100 kbps，逼近极限，要提波特率
- 两个通道都要 → 翻倍，必须提波特率或改二进制

```
初始化完成，DRDY 中断已使能
# 每行一个 CH1 原始码（24位补码）
# 电压(V) = 原始码 * 48.081e-9
20971
20970
20972
...（250 个正数）
-20969
-20971
...（250 个负数）
```

#### 逐行核对

| 行 | 应该是 | 不对说明 |
|---|---|---|
| `SystemCoreClock` | `72000000` | 不是的话 HSE 没起振，查晶振和负载电容 |
| `ID` | `0x53` | `0x00`/`0xFF` = SPI 不通 |
| `REG` 11 个字节 | 跟 `ads_cfg[]` 一模一样 | 不一样会直接报 FAIL |
| 数据 | 正负 20960 附近，每 250 个跳一次 | 见排错表 |

**关于 `REG` 这一行要注意执行顺序：** 回读校验（第 7 步）在
`ads_enable_test_signal()` **之前**执行，所以打印出来的永远是 `ads_cfg[]` 的原值
`02 A0 10 00 ...`，**即使开着测试模式也是 A0 和 00**。
测试信号是在这行打印之后才把 CONFIG2 改成 `A3`、CH1SET 改成 `05` 的，
串口上看不到这两个新值。想确认测试信号真的开了，看数据是不是方波就行。

## 七、排错表

| 现象 | 最可能的原因 | 怎么查 |
|---|---|---|
| 串口一个字都没有 | 波特率不对 / TX RX 接反 / USART1 引脚不是 PA9 PA10 | 换个波特率试，量 PA9 有没有波形 |
| `SystemCoreClock` 不是 72M | 8 MHz 晶振没起振 | 量晶振两脚有没有正弦波，查 22 pF 负载电容 |
| `ID = 0x00` 或 `0xFF` | SPI 完全不通 | ① 量 ADS1292 的 AVDD/DVDD 有没有电<br>② 查 SCK/MOSI/MISO/CS 接线<br>③ **确认 `__HAL_SPI_ENABLE` 那句在**<br>④ 用逻辑分析仪抓 SCK 有没有波形 |
| `ID` 读到别的值 | SPI 模式错 | CubeMX 里必须是 CPOL=Low, CPHA=2Edge（Mode 1） |
| `REG` 回读全是 `00` | **SDATAC 没生效** | 检查第 5 步在不在；把 SPI 降到 281 kHz 试 |
| `REG` 只有个别字节不对 | SPI 偶发错误 | 降 SPI 速度；检查 CS 时序；查地线 |
| 卡在「初始化完成」，无数据 | **DRDY 没有下降沿** | ① **量 PB0(START) 是不是 3.3 V** ← 最常见<br>② 量 PA0(DRDY) 有没有 2 ms 周期的脉冲<br>③ CubeMX 里 PA0 必须是 `GPIO_MODE_IT_FALLING` |
| 数据一直是 0 | CH1 关掉了 / MUX 选错 | 查 `REG` 第 4 个字节（CH1SET） |
| 数据是满量程 ±8388607 | 输入饱和 | 测试模式下不该出现，说明 MUX 没切到测试信号 |
| 波形一半正常一半尖刺 | **符号扩展漏了** | 检查 `v |= 0xFF000000` 那句 |
| `frame_err` 一直涨 | SPI 读错位 | 降 SPI 速度；查 CS 的 10 µs 延时在不在 |
| `rb_drop` 一直涨 | 串口跟不上 | 波特率提到 921600，或改二进制传输 |
| 数据跳变周期不是 250 个点 | 采样率不对 | 查 CONFIG1 是不是 `0x02` |
| 接电极后全是 50 Hz 干扰 | RLD 没工作 | 查 RLD 电极接没接、`REG` 第 6 字节是不是 `23` |

#### 怎么看那三个计数器

它们是全局变量，两种办法：

**方法 1（推荐）：调试器**
STM32CubeIDE 里 Debug 模式暂停，在 `Expressions` 窗口加
`frame_ok` / `frame_err` / `rb_drop`，直接看数值。

**方法 2：定期打印**
在主循环里加（临时调试用，会干扰数据输出）：

```c
static uint32_t last = 0;
if (HAL_GetTick() - last > 5000) {
    last = HAL_GetTick();
    uart_printf("# ok=%lu err=%lu drop=%lu\r\n",
                (unsigned long)frame_ok, (unsigned long)frame_err,
                (unsigned long)rb_drop);
}
```

正常情况：`ok` 每 5 秒涨 2500，`err` 和 `drop` 恒为 0。

## 八、常见疑问

**Q：为什么 CS 要用宏而不是直接写 `HAL_GPIO_WritePin`？**

宏展开后就是 `HAL_GPIO_WritePin`，只是拉高前自动加了 10 µs 延时
（手册要求的 4 tCLK）。全文有十几处 CS 操作，封装起来才不会漏。见 4.1。

---

**Q：`f[9]` 定义在中断函数里，会不会每次都很慢？**

不会。它在栈上，"分配"只是把栈指针减 9，一条指令的事。
而且中断不会嵌套自己，不存在两份同时存在的问题。

---

**Q：为什么读数据要 `spi_xfer(0x00)` 发个 0 出去？**

SPI 是全双工同步总线，**必须由主机产生时钟**，而产生时钟的唯一方式就是发数据。
所以读的时候发个无意义的 `0x00` 把时钟转起来，对方的数据才能被换进来。
手册 p42 明确说了读数据期间 DIN 保持低，所以发 `0x00` 是对的。

---

**Q：`% RB_SIZE` 会不会很慢（除法）？**

`RB_SIZE = 256` 是 2 的幂，编译器会自动优化成 `& 255`（一条与指令）。
**所以缓冲大小一定要取 2 的幂**：128、256、512。取 300 的话就真的会做除法了。

---

**Q：中断里能不能直接发串口？**

技术上能（150 + 700 = 850 µs < 2000 µs），`HAL_UART_Transmit` 跟 SPI 一样
是靠硬件 TXE 标志退出的，在中断里能正常发完。但**不建议**：

- **余量太小。** 用掉 43%，以后想加滤波、加校验、提采样率立刻就爆
- **超时保护同样失效。** `UART_WaitOnFlagUntilTimeout`（`stm32f1xx_hal_uart.c:3194`）
  是纯 tick 判断，连 SPI 那种软件计数器兜底都没有
- **失去了解耦。** 现在采样时序完全由 DRDY 硬件决定，串口快慢影响不到它；
  合并之后，串口一卡就直接丢采样点

---

**Q：为什么 EXTI0 优先级设成 3 而不是 0？**

0 是最高。设太高会长时间挡住其他中断。3 已经远高于 SysTick 的 15，
足够保证 DRDY 及时响应，同时给以后可能加的更高优先级中断留了空间。

---

**Q：`static` 是什么意思？**

对函数和全局变量，`static` 表示「**只在这个 .c 文件里可见**」，
别的文件访问不到。好处是避免和其他文件重名冲突，也让编译器能做更多优化。

（`print_i32` 里的 `static uint32_t last` 是另一个意思：函数内的静态变量，
出了函数不销毁，下次进来还是上次的值。）

---

**Q：数据怎么换算成电压？**

```
电压(V) = 原始码 × 48.081e-9
```

48.081 nV 是这么来的：

```
LSB = 2 × VREF / 增益 / 2^24
    = 2 × 2.42 V / 6 / 16777216
    = 48.081 nV
```

心电信号典型幅度 1 mV → 原始码约 20800，跟测试信号量级一样，正常。

---

**Q：为什么不用 DMA？**

可以用，会更省 CPU。但 9 字节的传输用 DMA 收益不大（配置 DMA 的开销
跟直接读差不多），而且会让代码复杂不少。现在 CPU 占用只有 43%，没必要。

## 九、想改东西改哪里

| 想改什么 | 改哪里 | 怎么改 |
|---|---|---|
| **切到电极采集** | `TEST_SIGNAL_MODE` | 改成 `0`，重新编译 |
| 采样率 250 SPS | `ads_cfg[0]` | `0x02` → `0x01` |
| 采样率 1000 SPS | `ads_cfg[0]` | `0x02` → `0x03`（记得提波特率） |
| 增益改成 12 | `ads_cfg[3]` | `0x00` → `0x40`（GAIN=100） |
| 打开通道 2 | `ads_cfg[4]` | `0x81` → `0x00`，然后在 ISR 里也解析 `f[6..8]` |
| 串口波特率 | CubeMX → USART1 | 改完重新生成，`MX_USART1_UART_Init` 会更新 |
| 缓冲区大小 | `RB_SIZE` | **必须是 2 的幂**：128 / 256 / 512 |
| SPI 速度 | CubeMX → SPI1 分频 | 现在 128 分频 = 562.5 kHz，最快可到 32 分频（2.25 MHz） |

#### 如果 rb_drop 一直涨

**方案 A（简单）：提波特率**
CubeMX 里把 USART1 改成 921600，串口助手也要跟着改。

**方案 B（彻底）：改二进制传输**
把主循环改成直接发 3 个字节的原始数据，不转文本：

```c
uint8_t pkt[4] = { 0xAA, (v >> 16) & 0xFF, (v >> 8) & 0xFF, v & 0xFF };
HAL_UART_Transmit(&huart1, pkt, 4, HAL_MAX_DELAY);
```

`0xAA` 是帧头，方便上位机同步。
4 字节 × 10 位 × 500 = 20 kbps，只有文本方式的 40%，还能顺便省掉 `print_i32`。

代价是串口助手里看到的是乱码，必须用 Python 脚本接收。
