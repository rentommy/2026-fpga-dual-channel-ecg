# ECG-with-Deep-learning-master 的可借鉴部分与改编

参考目录：`D:/ecg_fpga/模型训练/项目复现/ECG-with-Deep-learning-master`。本轮检查了数据处理代码、训练入口、CNN/CNNLSTM/GRU_CNN/SE_Net/SENetLSTM，以及数据处理和总结文档；原文件未修改。

## 实际代码与文档的差异

| 位置 | 实际行为 | 当前处理 |
|---|---|---|
| data/DealData.py | segmented_len=10，输出 3600 点；一段包含多拍 | 保留当前中心拍一个标签，不能照搬十秒输入 |
| data/DealData.py 标签分支 | 使用 label[0]，即首个非 N 标注；文档写的是数量最多的异常类型 | 不采用两者，直接使用中心原始标注 |
| data/DealData.py 正常分支 | N 与起搏 / 的组合标成 N | 不把起搏标注改成 N |
| train.py StandardScaler | 计算 std_data，但后续 expand_dims 的仍是 X | 当前单拍归一化与仅训练集拟合 RR 标准化均实际送入模型 |
| train.py StratifiedShuffleSplit | 按样本随机分层，没有记录/受试者分组 | 继续受试者隔离，201/202 同组；原成绩不能直接视作新受试者成绩 |
| train.py 训练与评估 | 训练标签转 one-hot，测试标签保持整数，但使用 categorical_crossentropy 的 evaluate | 不照搬，统一整数标签与交叉熵；单独计算逐类指标 |
| train.py 导出 | 活跃代码引用了仅在注释中定义的 checkpoint、ModelSavedPath | 本轮保存可直接加载的 PyTorch 权重及完整类别映射 |

原项目的 AAMI 变量名对应自选七个原始符号；不能仅凭变量名认定它执行了标准分组协议。当前继续明确保留原始符号。

## 数据处理方面

原项目有按导联读取、审查数据库注释、剔除无效数据和统一采样率的思路。这些值得保留。250 Hz 到 360 Hz 的固定时长重采样，与把不同长度单拍拉成同样点数是不同操作，不能混为一谈。本轮只用原始 360 Hz 的 MLII，因此不额外重采样采样率。

三位小数舍入、多数据库直接拼接、随机片段划分不会自动改善逐拍识别。本轮不引入这些变化，避免无法判断究竟哪个改动有效。原项目的总结提出了自编码器及 bagging/boosting，但所检查代码没有实现完整训练对照，不能作为已经验证有效的方法报告。

## 本轮已实现的结构对照

借鉴 `model/GRU_CNN.py` 的 CNN→GRU 和 `model/SENetLSTM.py` 的全局池化→压缩通道→hard-sigmoid 门控，建立三组共享卷积主干的七输出模型：CNN、CNN＋GRU、CNN＋SE＋GRU。最后两组只相差 SE，可直接比较这项变化。

为适应 288 点中心拍，卷积通道设为 16/32/48，卷积核 11/7/5，三次池化后保留 36 个时间步，GRU 隐状态 24。沿用 GroupNorm，三组使用完全相同的 RR 分支。不是原十秒 TensorFlow 网络的等价复现。

类别为 A/F/L/N/R/V/|，B/S 已从训练目标和输出删除。原候选序列仍保留用于边界和 RR，排除目标不改变相邻时间间隔。所有方案共用第三轮冻结的周期缩放数据和受试者划分、相同权重、学习率、25 轮上限及早停 6 轮。仅在验证集比较，不再次读取旧测试成绩。

旧测试已使用；本轮结果只作开发验证，不能代替新的独立最终验证。数据中的 L/R 来源不足仍存在，换结构并不保证解决。

## 运行与结果

在本目录运行 `../.venv/Scripts/python.exe run.py`。已有 runs 目录时拒绝覆盖。

`protocol.json` 保存训练前协议与数据哈希；`runs/` 保存源码快照、配置、权重、训练曲线、验证逐拍预测与混淆矩阵；`结果报告.md` 汇总实际结果。
