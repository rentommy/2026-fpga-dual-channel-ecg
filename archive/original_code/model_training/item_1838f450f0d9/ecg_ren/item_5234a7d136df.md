## 0. 数据与环境基线

### 0.1 数据集

四个 PhysioNet 数据库，按 10 秒窗口切分、重采样到 360 Hz（3600 点/样本）：

| 数据库 | 导联 | 窗口数 |
|---|---|---:|
| European ST-T Database | MLIII | 33 840 |
| MIT-BIH Arrhythmia Database | MLII | 8 280 |
| MIT-BIH ST Change Database | ECG | 4 842 |
| Sudden Cardiac Death Holter Database | ECG | 73 815 |
| **合计** | | **120 777** |

剔除无有效标注的 `Q` 类 2 514 个后，**实际训练数据 118 263 个样本**，按 9:1 分出测试集 11 827 个。

类别分布（窗口级）：

| 类别 | N | V | B | \| | A | L | R |
|---|---:|---:|---:|---:|---:|---:|---:|
| 数量 | 93 785 | 11 539 | 5 262 | 4 729 | 1 635 | 675 | 638 |
| 占比 | 79.3% | 9.8% | 4.4% | 4.0% | 1.4% | 0.6% | 0.5% |

> **勘误**：原代码注释称「N 占 96%」，实测为 **79.3%**（93785 / 118263）。

## 第 1 轮：原程序无法运行

### 问题 1-A：TensorBoard 未安装，训练启动即崩溃

**现象**：`main.py:121` 的 `model.fit()` 抛出

```
tensorflow.python.summary.tb_summary.TBNotInstalledError:
TensorBoard is not installed, missing implementation for tf.summary.scalar
```

**隐蔽点**：`tf.summary.create_file_writer()` 本身不报错，所以要等数据加载完（约 1~2 分钟）、进入第一个 epoch 才崩。

**解决**：`pip install tensorboard`（或移除 `callbacks=[tensorboard_callback]`）。

### 问题 1-B：读取 CSV 时内存溢出

**现象**：`main.py:43` 用 `dtype="str"` 读入后再转 float32。

**实测**：以 1000 行样本外推，`3ECGecg_data.csv`（1.6 GB）单个文件的字符串中间数组就需要 **6.38 GB**，而机器可用内存仅 6.7 GB，且此时已加载了 0.68 GB 数据 → 必然 `MemoryError`。

**解决**：直接按 float32 读取，并改为一次性拼接：

```python
X_parts = []
for i in tqdm(range(0, len(X_list)), desc="处理记录"):
    X_parts.append(np.loadtxt(X_list[i], delimiter=',', skiprows=1).astype('float32'))
X = np.concatenate(X_parts)
del X_parts
```

配套的内存优化：标准化改为原地运算（省两份 1.7 GB 临时副本）、切分完训练/测试集后 `del X, Y`。改后峰值约 3.5 GB，全量加载约 1~2 分钟。

### 问题 1-C：类别权重加到了错误的类别上（静默错误）

**现象**：程序能跑完，但结果是错的。

**根因**：`LabelEncoder` 按**字母序**编码，与代码中 `AAMI` 列表的顺序不一致：

| | A | B | L | N | R | V | \| |
|---|---:|---:|---:|---:|---:|---:|---:|
| LabelEncoder 实际编号 | 0 | 1 | 2 | 3 | 4 | 5 | 6 |

原代码写死了数字 `{0: 0.1, 1: 1.0, 2: 1.0, 3: 2.0, 4: 2.0, 5: 2.0, 6: 1.0}`，本意是「N 给 0.1」，实际效果：

| 类别 | 本意权重 | **实际生效权重** |
|---|---:|---:|
| N（占 79%，多数类） | 0.1 | **2.0** ← 反了 |
| A（占 1.4%，少数类） | 2.0 | **0.1** ← 反了 |

**权重完全颠倒**，训练会更严重地偏向多数类。

**解决**：按标签名查编号，不写死数字：

```python
weight_by_symbol = {'N': 0.1, 'L': 1.0, 'R': 1.0, 'V': 2.0, 'A': 2.0, '|': 2.0, 'B': 1.0}
class_weight = {int(le.transform([s])[0]): w for s, w in weight_by_symbol.items()}
```

### 验证

用每个 csv 前 2000 行构造的 8000 样本小数据集实跑，完整流程（加载 → 训练 → 评估 → 混淆矩阵 → 保存模型）全部通过。

## 第 2 轮：迁移到 PyTorch 以使用 GPU

**动机**：Windows 原生 TensorFlow 无法使用 GPU，CPU 训练需 3.2 小时/次，无法迭代实验。

**产出**：`main_torch.py`（Windows）、`main_torch_linux.py`（Linux）、`model/SENetLSTM_torch.py`。

### 逐层对齐的要点

Keras 与 PyTorch 的默认行为差异，不处理就会变成**另一个网络**：

| 项目 | Keras 默认 | PyTorch 默认 | 处理方式 |
|---|---|---|---|
| `hard_sigmoid` | `relu6(x+3)/6` | `Hardsigmoid` 同式 | 实测一致，直接用 |
| `'same'` + stride 3 | 自动补零，右侧多补 | **不支持 stride > 1** | 手写 `same_pad()`，补 (8,9)/(3,3)/(4,5) |
| BatchNorm | `momentum=0.99, eps=1e-3` | `momentum=0.1, eps=1e-5` | 改为 `momentum=0.01, eps=1e-3`（PyTorch 的 momentum 定义相反） |
| 权重初始化 | glorot_uniform + bias 0 | kaiming_uniform | `xavier_uniform_` + `zeros_` |
| LSTM 循环权重 | orthogonal | 均匀分布 | `orthogonal_` |
| LSTM 遗忘门 | `unit_forget_bias=True` | 无 | `bias_ih_l0[10:20] = 1.0` |
| `class_weight` | 逐样本加权后除 batch size | `CrossEntropyLoss(weight)` 除权重和 | 手动 `(losses * w).mean()` |
| `validation_split` | 取最后 20%，不打乱 | 无对应 | 照抄同样切法 |
| 数据布局 | `(N, L, C)` | `(N, C, L)` | `expand_dims(axis=1)` |

**参数量**：PyTorch 44 507 vs TensorFlow 44 467，差 40 个，来自 PyTorch 的 LSTM 有两组 bias（`b_ih` + `b_hh`）而 Keras 只有一组。属框架差异，非实现错误。

**GPU 优化**：混合精度（AMP）、`cudnn.benchmark`、整个数据集常驻显存（1.70 GB，避免每 batch 的 PCIe 传输——模型极小，传输才是瓶颈）。

程序跑完 60 轮后直接用内存中的 `model`（第 60 轮状态）评估，**没有加载最优 checkpoint**。

## 第 4 轮：四处改进（`main1.py`）

| 编号 | 改动 |
|---|---|
| ① | 评估前重新加载 val 最优权重 |
| ② | 测试结果落盘：`test_result_*.txt` + 混淆矩阵热力图 + 分类别指标 |
| ③ | EarlyStopping（patience = 10） |
| ④ | N 类别权重 0.1 → 0.4 |

同时修正了 checkpoint 中 `classes` 存为 `np.str_` 的隐患（torch ≥ 2.6 的 `weights_only=True` 默认值可能导致加载失败）。

### 对照实验结果

为分离「改动 ①」和「改动 ④」的贡献，在同一评估协议下跑两组：

| 运行 | N 权重 | 选点判据 | accuracy | macro-F1 | A precision | A recall | N 误判 |
|---|---:|---|---:|---:|---:|---:|---:|
| 原始 | 0.1 | 末轮 | 0.9005 | 0.8216 | 0.2771 | 0.7317 | 970 |
| w01 | 0.1 | val_loss | **0.8550** ⬇ | **0.7897** ⬇ | 0.2921 | 0.6768 | 1559 |
| w04 | 0.4 | val_loss | 0.9362 | 0.8552 | 0.4137 | 0.6280 | 521 |

### 关键发现：改动 ① 单独使用反而使结果变差

`w01` 相对原始运行只改了「用最优权重评估」，accuracy 却从 0.9005 掉到 0.8550。

**根因：选点标准与评价标准不一致。** EarlyStopping 与 checkpoint 都监控 `val_loss`，而该 loss 是**加权**的——N 权重仅 0.1，意味着目标函数几乎不惩罚 N 的误判。因此「val_loss 最低」的那一轮，恰恰是模型最激进地往少数类猜的一轮：

```
w01:  N → |  702 个 （预测为 | 的样本中 60.6% 实为 N）
      N → V  596 个
      N 合计误判 1559 / 9379
```

**改动 ① 本身没错，错在选点所用的指标。**

## 第 5 轮：改动 ⑤ —— 选点判据改用验证集 macro-F1（`main2.py`）

新增 `--monitor {val_macro_f1, val_loss}`，默认前者。checkpoint 与 EarlyStopping 统一监控该指标：

```python
higher_is_better = args.monitor == 'val_macro_f1'
score = va_f1 if higher_is_better else -va_loss     # 统一成越大越好
if score > best_score:
    ...保存 checkpoint
```

同时在 loss 曲线上叠加验证集 macro-F1（右轴）与选中轮次的标记线，使两个指标是否同步一目了然。

**验证**：用人为构造的错位序列（val_loss 第 11 轮最低，macro-F1 第 19 轮最高）测试，旧判据选中 macro-F1 仅 0.5076 的一轮，新判据选中 0.7032 的一轮，成功规避 w01 的失败模式。

**实际收益**（N = 0.4）：

| 运行 | 选点判据 | accuracy | macro-F1 |
|---|---|---:|---:|
| w04 | val_loss | 0.9362 | 0.8552 |
| w04_f1 | val_macro_f1 | 0.9434 | 0.8584 |

提升幅度不大。原因是 **N 权重提到 0.4 后，加权 loss 与 macro-F1 已基本同步**（见 `loss_curve_w04_f1.png`，两条曲线在第 20 轮附近同时走平），两个判据选出的轮次接近（33 vs 29）。

**该改动的价值在于扫参时的稳健性**——权重一旦改变，两指标可能再次错位。

### 验证集与测试集给出了不同的最优值

```
验证集 macro-F1:  0.8547 → 0.8719 → 0.8692    （0.7 见顶）
测试集 macro-F1:  0.8584 → 0.8629 → 0.8714    （仍在上升）
```

**应取 N = 0.7。** 超参必须用验证集选择；此处已在同一测试集上比较了 5 次，若挑「测试集最好的那个」，报出的数值是被测试集挑选过的乐观估计。两者差距（验证集 0.0027、测试集 0.0085）在噪声范围内。

### 精确率与召回率的对换

```
macro precision  0.8517 → 0.8714 → 0.8993  ⬆
macro recall     0.8675 → 0.8559 → 0.8487  ⬇
```

A 的召回率在 N = 0.7 与 1.0 时**均为 0.5061，完全不动**，而精确率持续上升（0.50 → 0.60 → 0.69）。说明模型对 A 的识别能力已到上限，继续加权只是在调整判定阈值的松紧。

原项目 `train.py` 读取 15 个 csv，其中 `X_SU30`~`X_SU52` 共 12 个是**猝死数据库按记录拆分**的结果，加上 `X_MIT`、`X_eu_MLIII`、`X_ST_ECG`，仍是同样 4 个数据库。

| 类别 | doc(七) | 按心拍重数 | 本复现 csv（窗口级） | 按窗口重数 |

### 7.2 架构一致

原项目 TensorBoard 记录的层名为 `conv1d ×3`、`batch_normalization ×2`、`dense`/`dense_1`/`dense_2`/`dense_3`（仅有 kernel 无 bias，即两个 SE 块）、`dense_4/5/6`（含 bias）、`lstm`，与本复现逐层一致。

### 7.3 差距的两个来源

**(1) 原项目未使用 class_weight（主因）**

`train.py:114`：

```python
savedModule=model.fit(X_train, y_train, epochs=num_epochs, batch_size=batch_size,
                      validation_split=0.2, callbacks=[tensorboard_callback])
```

无 `class_weight` 参数。本复现使用类别加权，是主动以整体准确率换取少数类召回率，掉 1~2 个点属预期内。

**(2) 原项目的标准化未生效**

`train.py:62-64`：

```python
ss = StandardScaler()
std_data = ss.fit_transform(X)    # 结果存入 std_data
X = np.expand_dims(X, axis=2)     # 但后续使用的仍是原始 X
```

`std_data` 计算后从未被使用，**原项目实际使用未标准化的数据训练**。本复现做了每样本去直流与标准化。这也使两边的 loss 数值不可直接比较。

### 7.4 原项目从未报告测试集结果

`train.py:120` 的 `model.evaluate(X_test, y_test)` 传入的是整数标签，而损失函数为 `categorical_crossentropy`（需要 one-hot），该行无法得到正确结果。原文所有曲线均来自 `validation_split` 切出的验证集。

**本复现的测试集结果是该项目的第一份测试集评估。**

> 另注：原文所称「98% 准确率」指 CNN-GRU 模型。从 TensorBoard 看，SENet-LSTM 为训练集 0.9775 / 验证集 0.9679，CNN-LSTM 为训练集最高 0.9892 / 验证集最高 0.9692，**训练集与验证集相差 1~2 个点**，引用时需注明口径。

## 第 8 轮：A 与 \| 表现不佳的根因分析

调参已至瓶颈：A 的 F1 仅 0.5845，`|` 为 0.7288。通过复算 `add_data.py` 的打标逻辑定位到**标注方案本身的系统性缺陷**。

### 标注规则

`Data/add_data.py:79-84`：

```python
non_N = [AAMI_MAP[s] for s in beats if s != 'N']
most = max(set(non_N), key=non_N.count)     # 出现最多的异常心拍
symbols_data.append(most)
```

**一个 10 秒窗口内只要出现 1 个异常心拍，整段即被标记为该类别。** 10 秒约含 10~17 个心拍。

### 实测标签纯度

直接读取 `.atr` 标注复算得到：

| 类别 | 窗口数 | 该类心拍占窗口比例（中位数） | 仅含 1 个异常拍的窗口 | 本复现 F1 |
|---|---:|---:|---:|---:|
| **B** | 5 255 | **100%** | 0.8% | 0.9952 |
| **L** | 675 | **100%** | 0.3% | 0.9624 |
| **R** | 631 | **100%** | 0.2% | 0.9508 |
| V | 11 868 | 12.5% | 51.0% | 0.9044 |
| **\|** | 4 486 | **15.4%** | 38.6% | 0.7288 |
| **A** | 1 563 | **14.3%** | **48.8%** | 0.5845 |

**标签纯度与 F1 高度对应。** L / R / B 接近满分是因为其 10 秒窗口内**全部**为该类心拍；而 A 类窗口中位数只有 2 个 A 心拍，其余约 8 个为正常拍——**信号 85% 与正常窗口相同，却被标记为 A**。

A 类窗口中异常拍个数的分布：

```
恰好 1 个 A:  763 个窗口 (48.8%)
恰好 2 个 A:  370 个窗口 (23.7%)
恰好 3 个 A:  124 个窗口 ( 7.9%)
6 个及以上 :  203 个窗口 (13.0%)
```

### 一个高度吻合的数值

含 **≥ 2 个** A 心拍的窗口占 **51.2%**，而模型的 **A 召回率为 0.5061**。

这强烈提示：**模型基本只能识别含 2 个以上异常拍的窗口，仅含 1 个的几乎全部漏检。** 这也解释了为何 A 的召回率在 N 权重 0.7 与 1.0 时纹丝不动——并非权重不足，而是该部分样本在信号层面就不可分。

### 为何 V 的纯度更低却表现良好

V 的纯度仅 12.5%，低于 A，F1 却达 0.9044。因为**室性早搏（PVC）的 QRS 波宽大畸形，单个即极为显著**；而**房性早搏（A）的差异主要在 P 波形态与提前量，与正常心拍波形几乎一致**，经卷积下采样后基本消失。

`|` 为「孤立的类 QRS 伪迹」，本身即为噪声标签，边界模糊，0.73 属合理水平。

### 结论

**在当前任务定义下，A 的 F1 约 0.58 已接近该标注方案的上限。** 原项目使用同一份数据与同样的标注规则，未报告分类别指标，其 A 与 `|` 大概率同样偏低。

## 待办与后续方向

### 已识别但尚未执行

1. **无加权对照实验** —— 关闭全部 class_weight，是唯一与原项目训练设置完全一致的配置，跑出的验证集准确率方可与 0.9679 直接对比。
2. **扩大模型容量** —— 当前 `LSTM(10)` 将 100 × 32 的特征压缩至 10 维，要在其中保留「3600 点中某一个异常心拍」的信息过于狭窄。建议提升至 `LSTM(64)` + `Dense(128/64)`。
3. **按心拍切分**（根本解法）—— 以 R 波为中心逐拍切片替代 10 秒窗口，可使 A 的标签纯度由 14% 提升至 100%。需改写 `add_data.py` 并重新生成全部 csv。原文引用的 Oh et al. (2018) 即采用此方案（论文标题含 *variable length heart beats*）。

### 已知方法学局限

- **按心拍随机划分而非按病人划分**：`StratifiedShuffleSplit` 按窗口随机切分，同一条记录的窗口会同时出现在训练集与测试集中（intra-patient 划分），会高估泛化性能。严谨做法应按记录划分。
- **L / R 样本来源单一**：L 与 R 仅存在于 MIT-BIH Arrhythmia 一个数据库中，测试集仅 67 / 64 个样本，其接近满分的指标不具备统计意义。
- **超参在测试集上比较了多次**：N 权重的 5 组实验均在同一测试集上评估，最终按验证集选定 N = 0.7 以规避该问题。
