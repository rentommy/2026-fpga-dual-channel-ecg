# DUT 接口契约 —— 多通道双延迟生物电滤波核

本文件是 **HLS 实现、测试平台、PS 侧驱动** 三方的共同依据。
数值参数在 `ecg_filter_coef.h`（由 `sim/gen_vectors.py` 生成，不要手改），
函数与结构体在 `ecg_filter.h`，本文件说明**约定**与**验收标准**。

---

## 1. 功能

每通道把一路生物电采样同时送进 `N_PATHS` 条滤波通路，各通路只差一个延迟量 `D`：

```
            ┌─ 延迟抽头 D[0] ─┐
x[n] ─ 温和高通 ─ yg ─┤               ├─ 减去 lp ─ 50Hz陷波 ─ FIR低通 ─ y[0]
         │          └─ 延迟抽头 D[1] ─┘                              └─ y[1]
         └─ 矩形窗基线估计 lp（L=320，两条通路共享）
```

逐点算式：

```
acc  += (x - acc) >> DC_SHIFT                 温和高通 fc=0.311 Hz，0 乘法
yg    = x - acc
sum  += yg - yg[n-DC_BOX_L]                   滑动求和，0 乘法
lp    = (sum * DC_BOX_SCALE) >> DC_BOX_FRAC   归一化 1/L，1 次乘法
对每条通路 p：
  y[p] = FIR( Notch( yg[n-D[p]] - lp ) )      5 + 16 次乘法
```

**为什么要延迟 `D`**：因果 LTI 系统的幅度与相位由 Bode 增益—相位关系绑定，
要压 0.5 Hz 以下漂移，带内相位就被锁死；唯一能改相位而不动幅度的是纯延迟。
矩形窗的群延迟恒为 `(L-1)/2`，取 `D=(L-1)/2` 即可一次对齐全部频率
（一阶 IIR 的群延迟在 0.05~1 Hz 内变 11 倍，对不齐）。

**为什么 L=320**：必须接近一个心拍（实测 RR 824/878 ms）。窗比一拍短时
窗里装着 QRS 和 T 波本身，基线被顶高，ST 系统性读低 —— L=256 实测偏差
−0.068 mV，已超过 0.1 mV 的临床判读阈值的一半。

## 2. 接口

### 2.1 单采样点核心

```c
void ecg_filter_sample(ecg_chan_state_t *st, ecg_sample_t x,
                       ecg_sample_t y[N_PATHS], ecg_range_t *rng);
```

- **纯函数 + 显式状态**，不含 `hls::stream`，用 `g++` 可直接做 C 仿真
- `y[p]` 对应输入 `x[n - (st->delay[p] + FIR_DELAY)]`
- `rng` 传 `NULL` 则不统计中间量峰值（综合时固定传 `NULL`，该路径会被优化掉）

### 2.2 块处理顶层

```c
void ecg_filter_block(const ecg_sample_t *in, ecg_sample_t *out,
                      int32_t n_samples, ecg_chan_state_t state[N_CHANNELS]);
```

数据按通道交织：

| 数组 | 下标 |
|---|---|
| `in` | `n * N_CHANNELS + ch` |
| `out` | `(n * N_CHANNELS + ch) * N_PATHS + p` |

### 2.3 每通道延迟配置

`DC_DELAY_CFG[N_CHANNELS][N_PATHS]` 给编译期默认值，`ecg_filter_init()` 可覆盖。
上板时建议映射到 AXI-Lite 寄存器，运行时可改。约束：`0 <= D <= DC_DELAY_MAX`，
且 `DC_DELAY_MAX < DC_BOX_L`（延迟抽头直接读矩形窗历史，不另开 RAM）。

| 配置 | D | 总延迟 | 用途 |
|---|---|---|---|
| `DC_DELAY_ECG` | 159 | 348 ms | 诊断：ST 测量、波形存档、模型推理 |
| `DC_DELAY_FAST` | 0 | 30 ms | 低延迟：实时显示、报警、肌电类闭环 |

### 2.4 时序与有效性

- 输入 500 SPS，每采样周期 200,000 个 100 MHz 时钟
- **前 `ECG_WARMUP` = 543 点（1.09 s）输出无效** —— 滑动窗未填满，上板丢弃
- 延迟是常数，无抖动：`总延迟 = D + FIR_DELAY` 个采样点，实测与计算一致

## 3. 位宽与定点约定

| 量 | 位宽 | 依据 |
|---|---|---|
| 输入/中间/输出样本 | `DATA_BITS` = 24 | ADS1292 原生；实测峰值占 17.8 位，余量 6.2 位 |
| 温和高通累加器 | `DC_ACC_BITS` = 34 | 24 + `DC_ACC_FRAC`(8) + 2 |
| 矩形窗滑动和 | `DC_BOX_ACC_BITS` = 34 | 24 + ceil(log2 320) = 33，留 1 位 |
| 陷波 / FIR 累加器 | `ACC_BITS` = 48 | DSP48 原生累加宽度；实测占 33.8 / 36.8 位 |
| 系数 | `COEF_BITS` = 18 | DSP48E1 的 25×18 系数端口原生宽度 |

**`DC_ACC_FRAC = 8` 的来历**：`acc += (x-acc) >> 8` 若用整数存会有死区 ——
`|x-acc| < 256` 时增量截断成 0，累加器卡住，死区 ±256 码 = ±0.0123 mV。
多留 8 位小数后死区降到 ±1/256 码。

**右移一律是算术右移。** 心电是有符号量且均值为负（实测 −3.942 mV），
逻辑右移会把负数变成巨大正数。测试平台开头有运行时断言兜底；
综合时用 `ap_int<N>`，其 `>>` 本身就是算术移位。

**舍入**：陷波、FIR、矩形窗归一化的移位都带四舍五入
（`(v + (1<<(s-1))) >> s`），比截断少一半偏差，硬件上只多一个加法。
温和高通的反馈移位用截断（反馈环里加舍入可能引入极限环），
其残留 DC 偏差 ≤1 码且会被 `lp` 一并减掉。

## 4. 验收标准

`tb_ecg_filter.cpp` 五项检查，任何一项不过返回非 0 退出码。

| # | 检查 | 阈值 | 抓什么 |
|---|---|---|---|
| ① | 实测 60 s vs 黄金参考 | 最大 64 码 / RMS 8 码 | 算术量化误差超预期 |
| ② | 单位冲激响应 vs 黄金参考 | 最大 64 码 | 系数装反、装错、折叠写错 |
| ③ | 50 Hz 纯音残留 | ≤64 码 | 陷波器没生效 |
| ④ | 各级中间量峰值 vs 声称位宽 | 不得溢出 | 位宽声明不成立 |
| ⑤ | 两条通路的延迟 | 必须精确相符 | 延迟线接错、读口偏移算错 |

比对一律跳过前 `ECG_WARMUP` 点。阈值取"理论上界 + 首次实测留约 20 倍余量"
（实测最大 3.3 码、RMS 0.698 码，阈值定 64 / 8）。

### 怎么跑

```bash
python sim/gen_vectors.py                       # 生成系数头 + 黄金向量
g++ -std=c++11 -O2 -I src/hls \
    src/hls/ecg_filter.cpp src/hls/tb_ecg_filter.cpp -o build/tb_ecg_filter
./build/tb_ecg_filter                           # 退出码 0 = 通过
```

Vitis HLS 里把 `ecg_filter.cpp` 设为 source、`tb_ecg_filter.cpp` 设为 testbench，
C 仿真和 C/RTL 协同仿真都直接可用，无需改动。

## 5. 实测性能

口径统一：全部跳过前 543 点热身，逐拍指标按临床定义
（每拍以自己的 PQ 段为基准），参考为零相位 `filtfilt`。

| 方案 | 延迟 | 典型漂移 调/验 | ST60 总误差 调/验 | T 峰总误差 调/验 |
|---|---|---|---|---|
| *旧定稿 移位 k=7×2（对照）* | 30 ms | 0.150 / 0.076 | 0.1081 / 0.1563 | 0.2273 / 0.2643 |
| 低延迟通路 D=0 | 30 ms | 0.276 / 0.130 | 0.0852 / 0.0898 | 0.1447 / 0.1670 |
| 诊断通路 D=159 | 348 ms | 0.039 / 0.022 | 0.0559 / 0.0688 | 0.0927 / 0.1152 |

单位 mV。"总误差" = √(偏差² + 标准差²)，偏差单列见 `report/llm_log/2026-10-19.md` §11。

读表要点：

- **诊断通路对旧定稿全面更好**：ST 好 1.9~2.3 倍，T 波好 2.3~2.5 倍，
  漂移好 3.5~3.8 倍，代价是延迟从 30 ms 增至 348 ms。
- **低延迟通路不是单纯改进**：同样 30 ms 下 ST/T 测量好 1.3~1.7 倍，
  但**基线平整度更差**（0.276 对 0.150）。两者是不同取舍。
- 定点 vs 浮点参考：最大偏差 3.3 码（0.158 µV），RMS 0.698 码（0.034 µV）。

## 6. 资源估算

### 乘法

| | 次数 / 采样点 |
|---|---|
| 矩形窗归一化（每通道共享） | 1 |
| 陷波 + FIR（每通路） | 5 + 16 = 21 |
| 每通道双通路合计 | 1 + 2×21 = **43** |
| 8 通道合计 | **344** |

每采样周期有 200,000 个时钟 → 占**一个 DSP48E1 的 0.172%**。
单通路时 176 次，0.088%。

### 存储

| | 位数 |
|---|---|
| 矩形窗历史 320 × 24（**兼作两条通路的延迟线**） | 7,680 |
| 滑动和 + 高通累加器 | 68 |
| *每通道共享小计* | **7,748** |
| 陷波状态 4 × 24 + FIR 历史 31 × 24 | 840 |
| *每通路小计* | **840** |
| 每通道（双通路） | **9,428** |
| 8 通道 | **75,424 bit = 4.1 块 BRAM18K = 器件的 1.5%** |

因为 `DC_DELAY_MAX`(192) < `DC_BOX_L`(320)，**延迟线不单独开 RAM**，
在矩形窗历史上多开一个读口即可 —— 每通道每通路省下 4,608 bit。

### 通道数上限

| 约束 | 上限 |
|---|---|
| 算力（1 个 DSP48，双通路） | 200,000 / 43 ≈ **4,650 通道** |
| 片上 BRAM（4.9 Mbit，双通路） | 4,915,200 / 9,428 ≈ **520 通道** |

**瓶颈是存储不是运算**，且通道数增加不引入任何额外延迟。

## 7. 综合流程

### 文件分工

HLS 专有的东西全部集中在 `ecg_filter_top.cpp`，核心保持纯 C ——
这样核心可以用 `g++` 秒级验证，换接口形式（m_axi / axis / ap_fifo）时核心不动。

| 文件 | 角色 | g++ 能编译 |
|---|---|---|
| `ecg_filter.cpp` | 纯 C 核心，无任何 HLS 写法 | 能 |
| `ecg_filter_top.cpp` | AXI 接口 + 综合约束 | 能（pragma 被忽略） |
| `tb_ecg_filter.cpp` | 核心级五项详细检查 | 能，秒级跑完 |
| `tb_ecg_filter_top.cpp` | 顶层级检查，供 csim / cosim 用 | 能 |

两个测试平台都向上逐级搜索 `data/` 目录，所以从任何工作目录启动都能跑
（Vitis HLS 的 csim 工作目录在 `<project>/<solution>/csim/build`，
靠 TCL 的 `-D` 传路径容易在引号转义上出错）。

### 跑综合

```bash
vitis-run --mode hls --tcl sim/run_csim_2026.tcl  # 精确位宽C仿真
vitis-run --mode hls --tcl src/hls/hls_fix.tcl    # 单DSP综合
vitis-run --mode hls --tcl src/hls/hls_export.tcl # 单DSP综合并导出IP
```

2026-10-23整理后，两个有效综合入口从项目根目录移至本目录，按脚本自身位置定位项目根目录；原有单DSP综合指令不变，仍输出 `hls_ecg2/`。两者含 `open_component -reset`，会重建该组件；已有IP可直接用于Vivado，不必因整理目录而重新综合。

器件 `xc7z020clg400-1`，时钟周期10ns，HLS调度实际为每时刻八通道合计1298周期。旧 `run_hls.tcl` 保留历史流程，不作为2026.1推荐入口；C/RTL协同仿真未验收，不能根据旧脚本存在而记为通过。对应历史尝试归档于 `old/hls_attempts/`。

`collect_hls_report.py` 与课题无关，任何 HLS 工程都能用，
自带 `--selftest`（不需要工具链即可验证解析逻辑）。

### 已加的约束

```c
#pragma HLS INTERFACE m_axi port=in  offset=slave bundle=gmem0 depth=32768
#pragma HLS INTERFACE m_axi port=out offset=slave bundle=gmem1 depth=65536
#pragma HLS INTERFACE s_axilite port=... bundle=ctrl
#pragma HLS ARRAY_PARTITION variable=st complete dim=1   // 8 通道各自一块 RAM
#pragma HLS ALLOCATION operation instances=mul limit=1   // 强制只用 1 个乘法器
#pragma HLS LOOP_TRIPCOUNT min=500 max=4096 avg=2000     // 让报告里的延迟有意义
```

旧版 `vivado_hls` 的 ALLOCATION 写法是
`#pragma HLS ALLOCATION instances=mul limit=1 operation`。

`ARRAY_PARTITION complete dim=1` 把 `st[8]` 拆成 8 个独立结构体，
每个里面的 `box_hist[320]` 仍是数组 → 各自映射到一块 BRAM，通道间不争端口。

### 外部端口为什么用 int32_t

AXI 要求字节对齐，`ap_int<24>` 不是。24 位只用在**片内存储**上
（`box_hist` / `fir_hist`），那里才是 BRAM 的大头 —— 比 32 位省 25%。
`ecg_filter.h` 里按 `__VITIS_HLS__` 条件切换：综合时用 `ap_int<N>`，
C 仿真时用原生整型。两边数值一致的前提是各级中间量都装得下，
由测试平台第 ④ 项核对（实测峰值占 17.8 / 24 位）。

### 预期数字

综合前按时间预算推算，可用来核对综合结果是否合理：

| 项 | 预期 |
|---|---|
| 每采样点乘法次数 | 344（8 通道 × 2 通路 × 21 + 8 × 1） |
| 每采样点周期数 | 约 344（1 个乘法器串行） |
| 采样周期可用周期数 | 200,000（100 MHz / 500 SPS） |
| 实时性占用率 | 约 **0.17%** |
| DSP48E1 | **1** |
| BRAM_18K | 约 **4~10**（取决于 HLS 的打包策略） |

综合结果与此有数量级偏差时，优先检查 ALLOCATION 是否生效、
`st` 是否被意外展开成寄存器。

## 8. 已知限制

1. **前 1.09 秒输出无效**，上板必须丢弃。
2. **诊断通路延迟 348 ms**，显示和报警都会晚这么多。心率不受影响
   （固定延迟在 RR 相减时抵消，实测 RR 误差反而更小）。
3. **肌电类闭环场景必须走低延迟通路** —— 文献要求 100~125 ms 以内，348 ms 不适用。
4. **`L=320` 与心率相关**。实测 RR 824/878 ms 时合适；心率显著偏离
   （如 <50 或 >110 bpm）时窗长与一拍的比例改变，ST 偏差会变大。
   让 `L` 跟随 RR 是有依据的改进方向，**尚未实现**。
5. **没有电极脱落检测**。实测电极脱落时输出会冲到 270 mV 量级（QRS 的 234 倍），
   目前没有任何机制识别并熄屏/冻结心率。建议补 EMRMS 包络检测。
6. **标定数据量**：两段 60 秒、一个被试。所有性能数字建立在 120 秒数据上，
   且"验证段"在调参中被反复查看，存在选择泄漏。详见 `report/why_fpga.md` §6。
