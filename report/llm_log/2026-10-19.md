# 大模型协作记录 2026-10-19

本日主题：把 10-18 那轮非线性探索收尾并定稿。
结果出乎意料 —— **整轮探索里唯一起作用的部分不是非线性，而是延迟补偿**，
而最终定稿的核心思路来自用户贴来的一条外部线索。

全天共 5 次模型自我纠错，其中 2 次推翻了模型自己前一条消息的结论。

---

## 1. 比较基准错了：拿两个不同工作点做对比

10-18 收尾时模型的结论是"定稿在典型条件下比方案 F 平 2.3 倍"。
用户追问"现在的 F 调的怎么样了"，模型把 F 的四个旋钮全扫了一遍，发现：

```
配置              典型mV  偏大mV  最坏mV  最差全拍  T波
定稿 LTI k=7x2    0.192  0.483  2.991  0.8539  49%
F k_g=7 x2级      0.124  0.233  0.554  0.8595  50%   ← 形态几乎相同
F k_g=8 x1级      0.415  0.775  1.276  0.9838  84%   ← 前一条报的那个
```

`k_g` 就是 F 自己的"用力程度"旋钮，模型当初随手取了 8（很温和）。
**把 F 调到和定稿同样的形态水平，它在三个漂移口径上全赢。**

前一条消息是拿定稿和一个**未调参的** F 比，等于比较两个不同工作点。
等形态对照后，F 族在每一个形态水平上漂移都更小，45 个组合里 34 个严格支配定稿。

## 2. 四个旋钮独立扫会漏掉交叉项

独立扫描时 `k_lp` 固定在 8、`w` 门限固定在 50/99 分位。
联合扫描发现 `k_lp=7` 配 `w=50/95` 比两者各自的"最优值"组合起来更好。

独立扫描只能找到坐标轴方向的局部最优，交叉项要联合扫才看得见。

## 3. 消融实验：整个"非线性"层是死重

把自适应权重 `w` 钉死为 1（等于拆掉整条非线性支路），指标**一模一样**：

```
                w加权  延迟   典型    偏大    最坏   最差全拍  ST-T   T波
定稿              -     -    0.192  0.483  2.991  0.8539  0.8746  49%
F 原样            有    有    0.051  0.098  0.528  0.9391  0.9836  72%
F 去掉 w          无    有    0.041  0.097  0.523  0.9402  0.9834  73%  ← 没变
F 去掉延迟         有    无    0.196  0.497  3.019  0.8544  0.8772  50%  ← 塌回定稿
F 两个都去掉        无    无    0.192  0.483  2.991  0.8539  0.8746  49%  ← 就是定稿
```

最后一行和定稿的数字**完全相同**，这不是巧合：`yg - lp` 在数学上就等于两级高通。
所以 F 的底座一直就是定稿，**延迟补偿是唯一加上去的东西**。

### 这推翻了 10-18 写进日志的一条结论

10-18 的记录里写过"跳出 LTI 取舍边界必须靠非线性/时变"。**这是错的。**
出路是允许**延迟**。原来那轮 LTI 扫描只扫了"级联一阶高通、不许延迟"，
**延迟线从来没进过搜索空间** —— 结论的适用范围被当成了普遍定理。

教训：声称"某类方法必然做不到"之前，先确认搜索空间里有没有被默认排除的维度。

## 4. 用户质疑：既然延迟不要钱，为什么不直接双向滤波

> 用户原话："延迟在这个产品里几乎不要钱，那为什么我不做十秒窗口的双向三阶巴特沃斯高通"

这个质疑戳穿了模型上一条里一句**没加界限**的话。模型说"延迟几乎不要钱"时
心里算的是 0.43 秒；10 秒窗 filtfilt 的延迟是 5~10 秒，差 12~23 倍。
**那句话在 0.43 秒成立，在 10 秒不成立，而模型没有写出这个界限。**

实测后承认用户在滤波质量上是对的：

```
方案                  延迟   典型   最差全拍  T波
F D=200              0.43s 0.153  0.9844  87%
双向 10s块+2s重叠      12s   0.113  0.9990  98%   ← 形态更好
双向 3阶在 0.05Hz 处：-120 dB，F 只有 -32 dB
```

**作为滤波器它全面更好**，而且顺带解决训练域不匹配。
不选它的唯一理由是延迟 12 秒 —— 波形晚 12 秒的监护仪不能用。

## 5. 启动瞬态污染了"最坏"这一列

双向滤波那张表里"最坏漂移"全是 3~4.5 mV，连理想的整段双向都是 3.060，反直觉。
查出来是**滤波器自己的启动瞬态**，出现在第 0.5 秒：

```
（去掉首尾2秒后）    调参段   验证段
定稿                1.292   1.614   ← 原报 1.683 / 2.991
F D=200            0.606   0.507   ← 基本没变
双向 整段           1.623   0.234   ← 原报 3.060 / 0.269
```

F 的最大摆动恰好在 2.0 秒，躲过了启动区，所以没被污染；定稿和双向都被污染了。
模型此前说"F 最坏比定稿好 4.9 倍"，按干净数据算只有 2.1 和 3.2 倍。

这是继 10-18 §18 之后，**同一个指标第二次被发现有问题**。

## 6. 预测实验：结构没问题，信息不够

> 用户原话："这个F方案不能体现fpga中我预想的实时性了，我想通过自适应逐渐预判
> 基线漂移，最终要实现形态准的同时有较低延迟"

先量天花板：用**真实的未来基线**（非因果，作弊）做补偿，30 ms 延迟下拿到
全拍 0.9896 / T 波 96%，**比延迟 430 ms 的 F 还好**。所以结构没有原理障碍。

但真实预测器全部失败。而且模型**第一版实现有 bug**：

- `lms2` 用了 `lp[n]` 和 `lp[n-1]` 两个抽头，但 `lp` 过采样约 1000 倍，
  相邻两点几乎相同 —— **这个矩阵是病态的**
- 抽头拉开到 100 点后，预测误差从 98~116% 降到 29~52%

模型还给错过一个数量级判断："0.3 Hz 推 0.12 个周期，很容易"。错在
**外推把斜率估计的噪声乘了 m 倍**，而且基线里的运动伪迹本质不可预测。

最终汇率（信号自身的性质，不是调参问题）：

```
预测步长 m    调参段误差   验证段误差
   40        6.4%      9.5%
  120       17.7%     28.2%
  200       32.7%     49.0%
```

## 7. "自适应能自己收敛"的假设被证否

模型假设在线 LMS 能按个体收敛、从而缩小固定 Wiener 预测器的泛化差距。
实测**反而放大**：

```
预测器                   调参段RMS  验证段RMS  泛化差距
固定 Wiener m=40          6.4%     9.5%    3.1pt
在线 LMS  m=40            9.4%    16.3%    6.9pt
固定 Wiener m=120        17.7%    28.2%   10.5pt
在线 LMS  m=120          52.5%    91.8%   39.2pt  ← 崩了
```

## 8. 异常输入测试推翻了模型自己的建议

模型基于"T 波 96% vs 90%"这一个标量推荐了自适应版。用户要求客观评价后，
模型补做了从未做过的异常输入测试：

```
异常输入            自适应版        纯延迟LTI版     权重模长
电极脱落 满量程 2s   1486 mV       270 mV        1.81→42.8
20mV 阶跃           11.0 mV       12.9 mV       2.1→3.4
掉线归零 1s          3.17 mV       3.00 mV       2.1→2.8
```

以及冷启动权重轨迹：`1s 1.019 → 5s 0.829 → 10s 2.180 → 20s 2.617 → 30s 2.092`
（所谓"稳态" 1.405，偏差 ±27~86%）。

**权重从来没收敛过，它在晃。** 这反过来解释了那个 96%：很可能只是晃动
在这段数据上碰巧停在了好位置 —— 同一行的 `全拍` 是 0.9732 对固定版的 0.9761，
**自适应版其实更差**。

模型当场收回建议：拿一个单一标量、两段数据、一个不收敛的系统，
去推荐了更复杂且有发散风险的设计。

## 9. 用户贴来的外部线索给出了定稿方案

> 用户贴了五个方案：半高斯自适应核 / 速度自适应因果滤波 / EMRMS 包络 /
> Savitzky-Golay 嵌入式优化 / 贝叶斯递归滤波

模型逐个评估，结论是三个已被测过或可证明赢不了、一个用于另一个问题、
**一个指对了方向**：

| 方案 | 评估 |
|---|---|
| 速度自适应因果滤波 | 已测（`var_timeconst.py` + `w` 加权），§3 的消融证明无贡献 |
| Savitzky-Golay | 边缘 S-G 本质是多项式外推。**3 抽头 Wiener 是给定抽头集下的 MMSE 最优线性预测器，S-G 的均方误差不可能更低** |
| 贝叶斯递归滤波 | 线性高斯卡尔曼 ≡ 递归 Wiener，同一个界。非线性模型版（EKF + McSharry）能赢但超出工期，且强形状先验会"编"出心拍 |
| EMRMS 包络 | 不治这个病，但**治另一个刚发现的病** —— §8 的电极脱落现在没有任何检测机制 |
| **半高斯核** | **指对了方向** |

### 半高斯的真正价值不在"高斯"，在群延迟平坦

```
核                   群延迟最小  最大  变化倍数
一阶IIR k_lp=8          22   249   11.25   ← 一个 D 只能对齐一个频率
半高斯 sigma=180        50   142    2.83
矩形窗 L=400           199   200    1.00   ← 最平坦
```

顺着这个诊断找下去，最优解是这个家族里**最简单最便宜的成员**：矩形窗。
它是滑动求和（加一次减一次），而且在平坦度这个指标上**比高斯更好**。

**必须说明的归属**：模型此前十二轮都没想到换基线估计器的核形状。
这个方向来自用户贴来的外部资料，模型做的只是把它的机理提炼出来并测量。

## 10. 模型第四次踩进同一个坑

把"仅 0.039 Hz 高通"方案标星推荐（全拍 0.9974 / T 波 104% / 30 ms），
而它的漂移是 0.815 mV。

**模板相关是在平均心拍上算的，平均 70 多拍正好把漂移抵消掉。**
这个盲点在本项目已踩过三次，还专门加了 T 波列去暴露它。

改用**逐拍 ST60 / T 峰误差**（按临床定义，每拍以自己的 PQ 段为基准）后排名整个翻转：

```
                     延迟    ST60误差RMS 调/验
定稿 LTI k=7x2        30ms   0.124 / 0.096
F 纯延迟 D=200       430ms   0.116 / 0.028
仅 0.039Hz 高通       30ms   0.136 / 0.194   ← 最差
```

此后所有决定改用逐拍指标。附带发现：`T波 104%` 超过 100% 是因为**参考自己那条
0.5 Hz filtfilt 也削了一点 T 波** —— 参考不是幅度真值，只是相位真值。

## 11. 报了标准差却称之为 RMS，掩盖了一个临床相关的偏差

模型报"矩形窗 L=256 的 ST60 RMS 0.0724"，**那其实是标准差，不含系统偏差**。
拆开后：

```
方案                 ST60偏差 调/验        ST60总误差 调/验
F 一阶IIR D=200      +0.0237/+0.0051  0.119/0.028
矩形窗 L=256 D=127   -0.0684/-0.0647  0.100/0.103
```

**L=256 有个稳定的 −0.068 mV ST 偏差。ST 压低 0.1 mV 就是临床判读阈值**，
系统性读低 0.068 mV 会造成假阳性 ST 压低。

原因：L=256 = 512 ms，**比实测 RR（824/878 ms）短**，窗里装着 QRS 和 T 波本身，
把基线顶高了。而"L 要取到约一个心拍"这条规则是模型自己在上一条消息里写下的，
**选 L 时却没照着做**。

加长到 L=320 后偏差降到 −0.028 mV，各项都变好。

## 12. 定稿

```
acc  += (x - acc) >> 8                    温和高通 0.311 Hz，0 乘法
yg    = x - acc
sum  += yg[n] - yg[n-320]                 滑动求和，0 乘法
lp    = (sum * 3277) >> 20                归一化 1/320，1 次乘法
y     = yg[n-D] - lp[n]                   D 每通道可配
```

| 通路 | D | 总延迟 | 典型漂移 调/验 | ST总误差 调/验 | T总误差 调/验 |
|---|---|---|---|---|---|
| 诊断 | 159 | 348 ms | 0.039 / 0.022 | 0.0559 / 0.0688 | 0.0927 / 0.1152 |
| 低延迟 | 0 | 30 ms | 0.276 / 0.130 | 0.0852 / 0.0898 | 0.1447 / 0.1670 |
| *（旧定稿 k=7×2 对照）* | - | 30 ms | 0.150 / 0.076 | 0.1081 / 0.1563 | 0.2273 / 0.2643 |

口径：全部跳过前 543 点热身，与测试平台一致。

诊断通路对旧定稿全面更好（ST 好 1.9~2.3 倍、T 波好 2.3~2.5 倍、漂移好 3.5~3.8 倍）。

**但低延迟通路不是单纯改进** —— 同样 30 ms 下 ST/T 测量好 1.3~1.7 倍，
基线平整度却更差（0.276 对 0.150）。模型最初写成"也比旧定稿好"，
是只看了 ST/T 两列没看漂移列。两者是不同取舍，不是单向改进。

写入 `src/hls/ecg_filter_coef.h`（含 `DC_DELAY_CFG[8][2]` 每通道延迟配置）、
`src/ps/hw_filter_ref.py`（追加三个函数，原有注释未动）、
`report/why_fpga.md`、`sim/experiments/plot_boxcar.py` + 效果图。

## 15. 当日后半程：接口契约与测试骨架

写出 `src/hls/ecg_filter.h`（契约）、`ecg_filter.cpp`（定点实现）、
`tb_ecg_filter.cpp`（C 仿真测试平台）、`INTERFACE.md`（规格书）。
测试平台五项全部通过，退出码 0。

定点 vs 浮点参考：**最大偏差 3.3 码（0.158 µV），RMS 0.698 码（0.034 µV）**。

### 实现阶段又发现三处

**① 测试平台抓出"黄金参考描述的不是硬件"**

冲激响应那项一开始失败，偏差 60780 码。查出来是模型自己埋的：
Python 的 `boxcar_lp` 在滑动窗没填满时**按实际点数求平均**，
而硬件只有一个固定的 `1/L` 常数乘法器，**没有除法器可以按实际点数平均**。

**黄金参考必须描述硬件真实行为，不是描述"理想算法"。**
改 Python 不改硬件：固定除以 L，窗没填满时等于拿 0 去补，
前 `ECG_WARMUP`=543 点输出无效、上板丢弃。

这一项正是测试平台该抓的东西 —— 如果冲激向量当初长于 543 点，
这个不一致会被"跳过热身"掩盖过去，一直带到上板。

**② 资源估算偏悲观一倍**

`report/why_fpga.md` 初版按"矩形窗历史 + 独立延迟线"算，得出双通路
18.7 kbit/通道、约 260 通道。写 HLS 时发现 `DC_DELAY_MAX`(192) < `DC_BOX_L`(320)，
矩形窗历史里本来就存着最近 320 个 yg，**延迟抽头直接多开一个读口即可**，
每通道每通路省 4,608 bit → 9.4 kbit/通道、**约 520 通道**。

而 BRAM 本身是双端口的，一个口读滑出窗口的样本、一个口读延迟抽头，正好用满。
**这个优化是写实现时才看见的，纸上推导时没想到。**

**③ 低延迟通路的描述写错**（见 §12 更正）

### 本段新增自我纠错

| # | 错误 | 如何发现 | 后果 |
|---|---|---|---|
| 28 | 称低延迟通路"也比旧定稿好" | 口径统一后重算三方对照 | 只看了 ST/T 列，漏看漂移列，描述偏向己方 |
| 29 | 资源估算多算了一条延迟线 | 写 HLS 实现时 | 通道数上限低估一倍 |
| 30 | 黄金参考实现了硬件做不到的算法 | **测试平台的冲激项失败** | 若向量再长一点就会被掩盖，带到上板 |

第 30 条值得记：**测试平台的价值不在确认已知正确的东西，在抓出"参考本身错了"。**
而它能抓到，恰恰是因为冲激向量只有 256 点、完全落在热身区内 ——
一个看起来是"测试向量太短"的缺陷，反而暴露了真问题。

## 16. 当日第三段：HLS 综合准备

本机没装 Vitis/Vivado，所以备齐全部文件：综合顶层 `ecg_filter_top.cpp`
（AXI 接口 + 约束）、顶层测试平台 `tb_ecg_filter_top.cpp`、
批处理脚本 `run_hls.tcl`、报告采集工具 `sim/collect_hls_report.py`。

把 `ecg_sample_t` 等类型做成按 `__VITIS_HLS__` 条件切换：综合时 `ap_int<24>`，
C 仿真时 `int32_t` —— **片内存储省 25%**，而 g++ 侧行为不变。
能这么做的依据正是测试平台第 ④ 项核对过的位宽余量（实测占 17.8 / 24 位）。

### 又抓出两处，都是模型自己的错

**① 顶层测试平台的检查 ③ 基于错误的心智模型**

最初写的检查是"把 path0 推迟 `D0-D1` 点后应当与 path1 一致"，实测差 11460 码。
查出来是**测试错了不是设计错了** —— 两条通路不是"同一个滤波器平移"：

```
path0 算 yg[n-159] - lp[n]
path1 算 yg[n-0]   - lp[n]
```

把 path0 推迟 159 点后它减的是 `lp[i+159]`，path1 减的是 `lp[i]` ——
**减的是不同时刻的基线估计**。11460 码 = 0.55 mV 正是基线在 318 ms 内的移动量。

改成冲激响应峰值位置核对，顺带验证了 `ch2` 被配成低延迟后 path0 确实落在第 15 点
（逐通道配置生效）。

**② 报告采集工具的实时性占用率算法是错的**

自检输出"占用率 594.30%"。原因：**HLS 报的延迟是整块的**
（一次调用处理 n_samples 个采样点），而我拿它直接跟**单个**采样周期比。
加 `--samples N` 折算后是每点 344 周期、占用率 0.15% —— 和综合前的手算完全吻合。

一个荒谬到一眼能看出的数字反而是好事；如果误差只有两三倍，大概率就混过去了。

### 本段新增自我纠错

| # | 错误 | 如何发现 | 后果 |
|---|---|---|---|
| 31 | 顶层检查基于"两通路是同一滤波器平移"的错误模型 | 检查失败后追查 | 差点去改没问题的设计 |
| 32 | 把整块延迟当成单点延迟算占用率 | 自检输出 594% | 若误差只有两三倍就会被当成真值写进报告 |

第 31 条的意思是：**一个失败的测试，第一件事是确认测试本身对不对。**
