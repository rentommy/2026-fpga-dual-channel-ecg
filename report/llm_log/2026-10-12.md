## 1. 把工程改成自包含、路径无关

**提示词**：你把用到的 FPGA 竞赛这个文件夹之外的那几个文件复制一份进来，
然后顺便把脚本的文件路径也改一下，改成相对路径，方便我分享给队友使用。

**问题的根源**：当时四个脚本里写的都是绝对路径，例如

```python
RAW     = r'D:\桌面\心率作业\上位机\演示数据.txt'
MODEL   = r'D:\桌面\心率作业\上位机\ecg_model.onnx'
CLASSES = r'D:\桌面\心率作业\上位机\ecg_model_classes.txt'
```

三个关键输入文件**在工程目录之外**。打包发给队友会直接跑不起来，
而且换盘符、换电脑、从别的目录启动都会断。

**处理**：

① 三个文件复制进工程。原始采集数据单独放 `data/source/`，
与 `data/` 下六个**生成**的测试向量分开 —— 因为前者**丢了就没了**，
后者随时能由 `gen_vectors.py` 重新生成。两类东西的备份策略不同，
不该混在一个目录里。

② 文件名改成英文（`ecg_60s_500sps.txt`）。
当时的理由是 Vitis HLS 对非 ASCII 路径不友好；
后来核对 §3.3.5.4 发现**这本身就是硬性提交要求**
（见 `2026-10-18.md` 第 8 条①）。

③ 四个脚本统一改成相对工程根目录推算：

```python
HERE = os.path.dirname(os.path.abspath(__file__))
ROOT = os.path.normpath(os.path.join(HERE, '..'))   # 工程根目录 ecg_fpga/
sys.path.insert(0, os.path.join(ROOT, 'src', 'ps'))
RAW  = os.path.join(ROOT, 'data', 'source', 'ecg_60s_500sps.txt')
```

关键是用 `__file__` 而不是当前工作目录 —— 这样**从任何目录启动都对**。

**验证**：改完后从 `C:\` 启动四个脚本，全部 exit 0，
结果与改动前逐位一致（50 Hz 残留 25.93 码、一致 4/5、QRS 1.175 mV）；
并确认工程下已无任何绝对路径残留。

**附带收益（当时没预料到）**：这次改造让 `2026-10-18` 把整个工程
搬到 `D:\ecg_fpga` 变成**零成本** —— 剪切粘贴，脚本一个字都不用改。

**可复用之处**：`__file__` 相对路径 + 源数据与生成数据分目录，
是任何要交付给别人复现的工程的标准做法。
→ 写进 `skill/` 的工程骨架模板

## 2. 一个必须注意的循环依赖

改路径时发现一处陷阱：`data/input_raw.txt` 看起来像是输入数据，
**但它是 `gen_vectors.py` 生成的副本**（该脚本读 `data/source/` 下的源文件，
再把它原样 dump 成 `input_raw.txt` 作为测试向量）。

**所以脚本绝不能指向 `input_raw.txt`** —— 那会变成"生成向量的脚本读自己的输出"。
两个文件内容几乎一样，但身份完全不同，混用不会报错，只会悄悄形成循环。
→ 写进 `skill/pitfalls.md`

## 3. 用户自写注释的审核：模型给出过宽的判断

**提示词**（用户贴出自己写的注释）：

```python
rows = [evaluate('① 原版 双向零相移 sosfiltfilt', ...)]   #双向 巴特沃斯带通 + 陷波(对比参考)
rows.append(evaluate('② 原版结构 改单向 sosfilt', ...))    #单向 巴特沃斯带通 + 陷波(对比参考)
```

> 我的注释写的对吗

**模型第一版回答**：两条都对，并顺带指出两条都写了"(对比参考)"。

**用户指出这个判断过宽** —— 问题正在于两条都写"(对比参考)"，
这**丢掉了两者角色的区别**：

| 行 | 真正的角色 |
|---|---|
| ① 双向零相移 | **天花板**。硬件做不到，它是性能上限 |
| ② 原版改单向 | **基线**。它是"什么都不改，只去掉反向滤"的对照 |

① 是"最好能到哪"，② 是"不动结构能到哪"。
两者在表里的作用完全不同 —— ③ 的各组候选要同时和这两条比：
比 ① 看损失了多少，比 ② 看改结构赚了多少。

都注成"(对比参考)"，读表的人就不知道该拿哪条当基准。

**这条的教训**：模型在审核别人的注释时容易只判断"事实有没有错"，
而漏掉"表述是否保留了必要的区分"。**注释的价值在于传达意图，
事实正确但意图模糊的注释仍然是需要改的。**
→ 写进 `skill/README.md`
