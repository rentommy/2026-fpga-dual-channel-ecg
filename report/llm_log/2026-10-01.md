## 1. 说过"竞赛应该用 HDL"，为什么滤波器用了 HLS

**提示词**：你不是说竞赛应该用 HDL 吗？

这是用户发现模型前后说法不一致提出的质疑。**质疑成立** ——
之前的表述没有说清"分工"，容易被理解成"全部用 HDL"。

**澄清后的分工**：

| 部分 | 实现方式 |
|---|---|
| ADS1292 SPI 主机 + 配置状态机 | **RTL（Verilog）** |
| 三级滤波链 | **HLS（C++）** |
| 系统集成（Block Design） | Vivado GUI + Tcl |
| PS 侧取数、显示、推理 | Python（PYNQ） |

**指南的依据**：§3.3.2 原文"实现方式不作限定。RTL、Vitis HLS、
AI Engine、PS 侧软件及其任意组合均可"，且对初级组推荐
"PL 侧以 **HLS 或 RTL** 实现计算核心并封装为 Overlay"。
**HLS 是指南自己的措辞，纯 HLS 都不违规。**

**那为什么不全用 HLS**：因为 §3.3.1.1 初级组的考察侧重是
"逻辑设计、**状态机**、**时序约束**、**接口协议**等基本 FPGA 设计能力"。
四项里三项是 RTL 的活。**全用 HLS 恰好在这个组最看重的地方交白卷。**

SPI 主机用 RTL 一个人就覆盖了"状态机 + 接口协议 + 时序约束"三项，
而且团队对 ADS1292 协议最熟，是写起来最省力、别人写起来最费劲的部分。

**那为什么滤波不用 RTL**：

1. **时间。** 零 FPGA 经验下手写 31 抽头折叠 FIR 的流水线、
   biquad 的反馈时序、定点截位，RTL 写得对但调得慢
2. **优化故事更好讲。** §3.3.5.5"性能与资源优化 20 分"要优化前后对比表。
   HLS 里加一条 `#pragma HLS PIPELINE` 就能拿到真实的
   "II 从 3 降到 1、DSP 从 x 变 y"数据，改参数重综合一次即可。
   RTL 要拿同样对比等于把模块写两遍
3. **C 仿真能直接对黄金参考。** HLS 的 C 仿真就是普通 C++ 程序，
   几秒跑完 60 秒数据、直接读 `golden_float.txt`。
   RTL 要先写 testbench、搭文件读写、跑 xsim，一次几分钟

**一句话结论：接口和时序用 RTL，数据通路用 HLS。**
这是工业界本来的分法，也正好对上初级组考察点和时间预算。
三种手段都用到并说清各用在哪，比单一手段更像一件完整作品
（§3.3.2"鼓励综合考虑软硬件协同"）。

→ 这一节直接构成报告 §3.3.5.3 要求的"软硬件划分依据与接口设计"

## 2. 学习节奏：用户要求停下来自己弄懂

**用户原话**：

> 你进度太快了，我还不知道滤波器要怎么设计，你的 py 程序是怎么模拟
> 然后选择的滤波器结构，你告诉我我要学的东西和大概步骤，
> **我要自己一步一步弄明白这个前期的 py 程序**

**这是本项目协作方式的分界点。** 在此之前模型一直在产出新代码，
用户被动接收；此后改为：模型停止产出新代码，逐行讲解已有脚本，
用户自己写注释、自己提问。

**为什么这个调整是必要的而不是拖进度**：

§3.3.3.1 要求提交"体现大模型协作过程的交互记录"，
§3.3.5.5 单列"大模型协作与技能包 15 分"。**评分看的是协作，不是代拍。**
如果参赛者讲不清自己代码里每个常量的来历，
报告里的"设计依据"就只能是模型给的说法，答辩时站不住。

实际效果：此后用户自己在 `evaluate_chains.py` 等文件里写了大量注释
（并主动要求模型审核，见 `2026-10-12.md`），
并在 `2026-10-17` 自行发现了"报告引用的一致性数字不是定稿配置"这类问题的线索。

→ 写进 `skill/README.md` 的"与大模型协作的节奏"一节
