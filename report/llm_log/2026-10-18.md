## 1. 报告里的系数值和头文件里的对不上

**问题**：报告 §2.3 写"Q2.16（整数位 2，容纳 ±1.618）"，
而 `ecg_filter_coef.h` 里是 `NOTCH_B1 = -103864`。两个数对不上。

**模型回答（第一版，错的）**：1.618 来自 `-2cos(2π·50/500) = -1.6180`，
是陷波器 b1/a1 的理论值，没问题。

**实际核算**：`-103864 / 2^16 = -1.5848`，不是 1.6180。

**自我纠错**：`scipy.signal.iirnotch` 返回的系数**已经除以 (1+α)** 归一化过，
α = sin(ω₀)/2Q。所以

```
-2cos(2π·50/500)                = -1.6180    ← 推导中间量
÷ (1 + α)                       = -1.5848    ← 真正存进硬件的
```

−1.6180 是教科书公式里的中间量，**从来没有进过硬件**。
而且 α 跟 Q 有关，**换 Q 值这个数还会变**，所以不能照公式手算，
必须从 `notch_coef()` 的实际返回值取。

**影响面**：同一个错误数字出现在 **4 处**（`gen_vectors.py` 的 docstring
和常量注释、`report/design_phase1.md` §2.3、`滤波器学习清单.md`）。
评委只要重算一次 −103864/2¹⁶ 就会发现报告和代码不一致。

**修正后的验证**：改完重跑 `gen_vectors.py`，
**头文件逐字节与改动前一致** —— 确认改的全是注释，一个系数没动。

**可复用之处**：凡是"报告里的数"和"代码里的数"重复存在的地方，
都要能一步互算验证。这次能发现是因为头文件存的是整数、
报告写的是浮点，两者可以交叉核验。
→ 写进 `skill/pitfalls.md`

## 2. 同一个判断错了两次

这条是本次会话里最有价值的纠错轨迹，因为**错了两轮才对**。

**问题**：报告用"注入 2 mV / 0.2 Hz 正弦"测漂移抑制。
用户质疑：实测数据本身就有很多干扰，为什么不直接用实测数据测？

**模型回答（第一版，错的）**：那 60 秒录得挺稳，本来就没多少基线漂移，
所以要注入一个比实测严厉 8 倍的干扰。

**实际测量**：为此写了 `sim/measure_wander.py`，结果直接推翻上述说法：

| | 实测 | 注入正弦 |
|---|---|---|
| 0.05–0.5 Hz RMS | 1.008 mV | 1.414 mV |
| 峰峰值 | **6.613 mV** | 4.000 mV |

**峰峰值上实测比注入更大。** "本来就没多少漂移"是凭印象说的，
而且"严厉 8 倍"是拿单频比单频，和频带能量不是一回事。

**模型回答（第二版，还是错的）**：改口说"实测漂移的能量大部分散在
0.1 Hz 以下，那里衰减更强，所以实测不够严苛"。

**实际结果**：新写的脚本自己的输出就否定了这条 ——

```
0.05 Hz  0.219 mV
0.10 Hz  0.058 mV
0.20 Hz  0.252 mV   ← 最大的单频分量在这里
0.30 Hz  0.134 mV
0.50 Hz  0.101 mV
```

0.20 Hz 是**最大**的单频分量，不是"能量集中在 0.1 Hz 以下"。

**第三版（经得起数据检验的）**：三个事实放在一起才读得对 ——
峰峰值很大（6.613 mV）、频带 RMS 中等（1.008 mV）、
但**没有任何单频超过 0.252 mV**。结论是实测漂移是
**偶发的大幅摆动**（动一下、深呼吸一次），能量散在整个频带，
不是某个频率上的稳态振荡。

所以注入和实测**测的是两件不同的事**：

| | 测什么 | 能得到什么 |
|---|---|---|
| 注入稳态正弦 | 稳态衰减 | 能算出 dB，可扫强度 |
| 实测偶发摆动 | 瞬态恢复 | 真实场景的表现 |

两者都需要，不互相替代。报告 §2.1 按这个口径重写，
并明确写了"注入数据一行都没有进过测试向量"。

**这条的教训有两层**：
① 凭印象描述数据会错，而且第一次改错之后**很容易再编一个同样没验证的理由**；
② 真正的解法是**写一个脚本把数量级摆出来**，让说法有数据支撑，
而不是换一套更好听的措辞。
→ 写进 `skill/pitfalls.md` 和 `skill/README.md`

## 3. 报告里引用的"一致 4/5"不是定稿配置的数字

**发现过程**：逐行走查 `evaluate_chains.py` 的 `check_inference()` 时发现

```python
hw_y = hw.chain_hw(raw, k=8, notch_q=30.0, n_taps=31)
```

而定稿是 **k=7 / 直流阻断 2 级 / Q=15**。四个参数差了三个。

更根本的原因：`hw_filter_ref.py` 的 `chain_hw()` **根本没有 `stages` 参数**，
内部固定调用 `dc_block_shift()` 单级。所以那张候选对比主表里，
**定稿配置从头到尾缺席**，六组候选全是单级。

**修正**：给 `chain_hw()` 加 `stages` 参数（默认 1，保证已有六行结果不变），
把定稿组合补进候选表，并把推理一致性改成测定稿配置。

**实测结果（出乎预料）**：

| | 心拍形态相关 | 残留直流 | 模型一致 |
|---|---|---|---|
| k=7 Q=15 FIR=31 单级 | **0.9553** | 0.012 mV | 4/5\* |
| k=7 Q=15 FIR=31 **2 级（定稿）** | 0.8550 | 0.000 mV | **2/5** |

\* 单级那个 4/5 是 k=8 Q=30 测的，严格说也不同配置

**定稿配置反而更差**，而且不是随机翻转：

```
零相移参考    N  N  N  A  A
定稿硬件链    A  A  A  A  A      ← 全部压向 A
```

参考判读前三个窗口为 N（正常），定稿链全读成 A（房性早搏）——
**系统性偏移**。

**机理分析**：两级 0.622 Hz 高通等于二阶，把 P 波和 PR 段的低频成分
削得比一级狠。而房早的判读高度依赖 P 波形态与时序，
P 波被削弱变形后正常搏动被读成房早。

对照更扎眼：0.8550 和"原版结构改单向"的 0.8496 几乎相同 ——
**换硬件结构挣来的形态优势，被第二级直流阻断丢回去了。**

**当前状态：已决，见第 3b 条。** 结论是 `DC_STAGES = 2` 保持不动，
而 2/5 这个问题不在级数上。

**这条的可复用之处**：参考实现的函数签名如果缺一个维度，
那个维度上的配置就**无法出现在任何对比表里**，而表格看上去是完整的。
缺口不会报错，只会安静地缺席。
→ 写进 `skill/pitfalls.md`

## 3b. 级数之争：模型拿错了数，给出了反的建议

**模型建议（错的）**：把 `DC_STAGES` 从 2 退回 1。
理由是"残留直流 0.012 mV 只占 QRS 幅度 1.149 mV 的 1%，完全无害，
而形态相关掉 0.1 是实打实的损失"。

**错在哪**：0.012 mV 是**静态直流失调**的残留，
不是**基线漂移**的残留。拿错了量。

**补测（`sim/measure_wander.py` 新增第 ④ 节）**：

| 级数 | 漂移残留 RMS | 漂移残留峰峰 | 峰峰/QRS | QRS | 心拍形态 |
|---|---|---|---|---|---|
| 1 | 0.425 mV | **3.203 mV** | **278.7%** | 1.149 | 0.9553 |
| 2 | 0.266 mV | 1.683 mV | 143.2% | 1.175 | 0.8550 |
| 3 | 0.208 mV | 1.371 mV | 114.3% | 1.199 | 0.7311 |

1 级的基线摆动是 QRS 高度的 **2.8 倍** —— 波形会荡出屏幕，
ST 段根本无从测量（参见 `2026-10-03.md`：ST 段本来就难测准）。

**修正后的结论**：`DC_STAGES = 2` 正确，保持不动。
而且 2 恰在拐点上 —— 1→2 残留降 47%，2→3 只再降 18%，形态却掉得更快。

### 为什么级数增加会伤形态：判决性实验

既然不是"幅度削太多"，就得查清真正的机理。
把移位式直流阻断写成等效传递函数

```
acc[n] = (1-s)·acc[n-1] + s·x[n]        （s = 1/2^k）
y[n]   = x[n] - acc[n]
=>  H(z) = (1-s)(1 - z⁻¹) / (1 - (1-s)z⁻¹)
```

（与 `dc_block_shift` 的最大偏差 8.7e-11 码，确认是同一个滤波器）

然后**同一个幅度响应跑两遍**，只换因果/零相移：

| 级数 | 因果 残留峰峰 | 因果 形态 | 零相移 残留峰峰 | 零相移 形态 |
|---|---|---|---|---|
| 1 | 3.203 mV | 0.9553 | 3.043 mV | **0.9950** |
| 2 | 1.683 mV | 0.8550 | 1.726 mV | **0.9845** |
| 3 | 1.371 mV | 0.7311 | 1.065 mV | **0.9719** |

**零相移下三种级数的形态相关全部 ≥ 0.97**，而因果版本一路崩到 0.73。
两边残留幅度几乎相同（1.683 vs 1.726）——**幅度这个变量被排除**。

量化依据：单级在 0.2 Hz 是 **−10.3 dB / 72.2°**，
级联时幅度和相位**一起累加**（2 级 144.5°，3 级 216.7°）。
而训练用的滤波器在同一频率是 **−63.7 dB / 0°** ——
衰减比我们狠 43 dB，却完全不带相位失真。

**结论：原因是相位失真，而相位失真是因果滤波的固有代价。**
任何能把基线压住的级数都会带相位失真，所以 2/5 这个问题
**不可能通过调 `DC_STAGES` 解决**。

### 由此确定的软硬件划分

| 通路 | 滤波方式 | 服务于 |
|---|---|---|
| FPGA 实时链 | 因果，流式 | 显示、心率、ST 测量（8 通道 × 500 SPS，每样本） |
| PS 推理链 | `filtfilt` 复刻训练参数 | 模型判读（每 10 秒一次，单通道） |

成本几乎为零：PS 侧本来就按 10 秒窗口推理，数据已在内存，
加一句 `filtfilt` 即可；并顺带消掉 **34 Hz vs 40 Hz** 低通差异
（训练用 34 Hz，硬件链用 40 Hz，这也是域偏移的一部分）。

**这条同时是 §3.3.5.3 要求的"软硬件划分依据"**：
实时连续通路与块式推理通路的吞吐要求不同，故实现方式不同 ——
而且这个划分是**由实测数据逼出来的**，不是设计之初的猜测。

**这条的教训**：给建议前先确认用的是**哪个量**。
"残留"在这个项目里至少有三个意思（静态失调残留、漂移频带残留、
工频残留），数量级差几十倍，混用会得出完全相反的结论。
→ 写进 `skill/pitfalls.md`

## 4. 另一处"评估了造不出来的配置"

**发现**：`sim/decide_dc_block.py` 第 116–128 行仍在扫 Q1.15（`fb=15`），
而它的 `quantize()` 没有范围检查：

```python
def quantize(c, fb):
    s = 1 << fb
    return np.round(np.asarray(c) * s) / s     # 没有范围检查
```

1.5848 × 2¹⁵ = 51932，早就超过 16 位有符号上限 32767。
但代码不报错，照样算出一组漂亮的性能数字 ——
**那组数字描述的是一个物理上造不出来的配置。**

对照 `gen_vectors.py` 的 `to_fixed()`，它有 assert，所以不会犯这个错。

这也顺带解释了 09-30 记录里那条断言报错 `[32096, -51932, 32096]`
中 −51932 的来历。

**这条的可复用之处**：量化函数**必须带范围检查**。
没有检查的量化函数会让你对不可实现的配置做出结论，
而且结论看起来完全正常。
→ 写进 `skill/fixed_point_helper.py`

## 5. 硬件上怎么做除法

**问题**：直流阻断里的 `(x - acc) / 128`，硬件怎么实现？

**模型回答**：`>> 7` **就是**那个除法。一个数在硬件里是一排导线，
"右移 7 位"意思是把第 7 号线接到原来第 0 号线的位置 ——
**没有门电路、不花时间、不占 DSP**。

但这只在除数是 2 的幂时成立。这正是选 1/128 而不是"理想"的 1/159.2 的原因：
代价是截止频率被动变成 0.622 Hz 而不是 0.5 Hz。

**追加的坑（模型主动提出）**：心电数据是**有符号**的，所以
- Verilog 必须用 `signed` + `>>>`（算术右移）
- HLS 必须用 `ap_int<N>`，不能用 `ap_uint<N>`

用逻辑右移会把每个负样本变成一个巨大的正数。而心电信号的直流失调是
−3.94 mV，**绝大多数样本都是负的** —— 这个错误会让输出完全失效，
但在"只看小信号"的测试里可能不暴露。
→ 写进 `skill/pitfalls.md`

## 6. 两个 Python 侧的陷阱

**① 黄金参考必须无条件 float64。**

`dc_block_shift()` 用 `np.empty(len(x), dtype=np.float64)` 而不是
跟随输入的 dtype。如果跟随输入（整型）的 dtype，
参考实现就会**悄悄复现硬件的截断**，从而失去参考的意义 ——
参考自己也犯同样的错，比出来差异为零，标尺就废了。

**② `np.asarray` 在 dtype 已匹配时不复制。**

验证过：对 `np.asarray` 的返回值写入会**污染调用方的数组**

```
x 被改了: [99.  2.  3.]
```

所以参考实现里凡是要就地写的地方，都必须用 `np.empty` 新建数组，
不能用 `np.asarray`。
→ 两条都写进 `skill/pitfalls.md`

## 7. 原始数据第一行的异常值

**问题**：`data/source/ecg_60s_500sps.txt` 第 1 行是 `402`，
而其余 30033 行全在 −113760 ~ −76000 之间。

**溯源**：该文件是 `上位机/演示数据.txt` 的改名副本，
写它的是 `ecg_monitor.py` 的串口接收线程。
问题在开始接收的瞬间：STM32 一直在发，上位机 `reset_input_buffer()`
清空缓冲后开始读，**第一块字节几乎必然从某个数字的中间开始**。

若 STM32 当时在发 `-113402\n`，上位机只接到尾巴 `402\n`，
而 `int('402')` **是合法整数**，于是被当成正常样本存了进去。
推断原值为 −113402 —— 正好落在邻居 −113461 和 −113351 之间。

**为什么只有这一个文件有**：另外三个采集文件（`最佳片段.txt`、
`测试.txt`、`验证数据.txt`）开头都正常。这取决于开串口瞬间落在字节流哪里；
截出的碎片不是合法数字时会被 `except ValueError` 吃掉，不留痕迹。
**只有碎片恰好是纯数字时才会混进来** —— 概率事件，四次中了一次。

**代码里的不对称**：该解析已处理**尾部**半行（`pending = parts.pop()`），
但**头部**半行没有任何处理。

**影响评估（实测）**：

```
带第1行(402)   心拍 73  QRS 1.1479 mV  心率 72.73 BPM
去掉第1行      心拍 73  QRS 1.1479 mV  心率 72.73 BPM
```

指标一个数都没变。原因有两个：统计都掐掉了前 2 秒躲开启动瞬态；
R 波检测阈值用 **98 百分位**而非最大值，单个野值顶不起阈值 ——
这个设计选择在此处意外救了场。

**结论**：当前数据不用动，但上位机解析应修（打开串口后丢弃第一个
换行之前的全部字节），否则下次采集还会中，且若截出的是大数就不无害了。
→ 写进 `skill/pitfalls.md`

## 13. 用户提出双链路构想

> 用户原话："先都不做，先看看我的滤波想法，既让直流阻断一阶时心拍形态相关度很好，
> 高阶时阻断效果又很好，我能不能一个数据进行两个链路滤波，每个链路分别保留优点
> 最终再合并为一个输出。"

这个构想直接命中了上午 §3b 留下的死结：LTI 空间里"压漂移"和"保形态"严格对立。

模型补充了一条数学约束：**两条 LTI 链用固定权重合并，结果仍是一条 LTI 链**
（`Y = (w_A·H_A + w_B·H_B)·X`），所以合并权重必须**依赖信号本身**才有意义。
由此确定实现形式：

```
y = y_gentle - w · (acc_aggr - acc_gentle)
```

两条链的差恰好等于两个基线估计之差，不必真算两条链。

新建 `sim/experiments/`，本轮全部脚本落在此目录，作为否证记录保留。

## 14. 模型给错前提，用户据此提出的方案被白白证伪

模型把门控方案里 ST-T 相关下降归因于"门控解除后 acc 追赶基线的瞬态"。
用户顺着这个前提提出改进：

> "改成到门控之前用斜率预测门控结束时的基线大小，在门控这个阶段虽然不更新
> 但是按照预测的水平来走，防止门控结束后追赶基线照成的波形干扰"

实现为 `slope_hold.py` 并画出按 R 波对齐平均的基线曲线后，**前提被否定**：
冻结段平均只有 **1.6 个采样点**，根本形不成追赶瞬态。真实原因是强阻断链
**直接吃掉了 0.26 mV 的 T 波**。

**这条是本次协作里代价最大的一次错误** —— 不是模型自己绕了弯路，而是
模型提供的错误机理让用户花了一轮去设计一个解决不存在问题的方案。

教训写进技能包：**归因要有能证伪它的测量，不能只是"说得通"。**

## 15. 检测量污染源归因错误

模型称合并权重 `w` 的检测量 `d` 被"QRS 污染"。按 R 波对齐平均后实测：

| 位置 | 幅度 |
|---|---|
| R 峰前 40 ms（QRS） | 小尖峰 |
| R 峰后 220 ms（T 波） | **主要成分，远大于 QRS** |

主污染源是 T 波不是 QRS。这直接影响门控窗口该开在哪 ——
按错误归因去设计，门控会开在完全不起作用的位置。

## 16. 扫描结果和模型的处方相反

模型建议"把强阻断链的截止频率降下来，减少它对形态的伤害"。
`sweep_aggressive.py` 扫完的结论相反：双链结构里强链的输出被 `w≈0.1` 稀释，
它对形态的伤害本来就被摊薄了，**应当纯粹按"压漂移"去优化**，不该向形态妥协。

模型把单链路的直觉直接搬到了双链路上，没有先算权重的稀释作用。

## 17. 用户发现残留基线右偏 —— 整轮最大的单次改进

> 用户原话："我观察到残留基线有向右偏移，你有做对齐之后再减去吗"

**没有做过任何对齐。** 方案 F 的残留基线估计 `lp` 是一阶 IIR，
k=8 时时间常数 `2^8/500 = 0.512 s`，等于一直在用"半秒前的基线"减现在的信号。
原实现 `y = yg - w·lp` 完全没有补偿这个滞后。

加上延迟补偿 `y[n] = yg[n-D] - w[n]·lp[n]` 之后，是整轮探索中**单次改进幅度最大的一步**。

这一步后来被证明是整个方案里**唯一真正起作用的部分**（见 2026-10-19 §3 的消融实验）——
而它来自用户对波形图的肉眼观察，不是来自模型的任何推导。

## 18. "漂移峰峰"是纯最坏值统计

画出 `plan_F_aligned.png` 后，图中第 ③ 栏和模型报的数字**视觉上矛盾** ——
图里定稿明显比 F 平，数字却说 F 更好。追查发现：

```
漂移峰峰 (mV)     整段60s   图中窗口52-60s   2秒窗中位数
F D=80            1.276      1.229          0.413
定稿 LTI          1.683      0.330          0.179
```

"峰峰值"只反映**整段里最糟的那一次摆动**。换成 2 秒窗中位数，
定稿在典型条件下比 F 平 2.3 倍。

**此前所有方案对比都只用了峰峰值这一个数**，等于用一次最大摆动代表全部表现。
而且画图时选的恰好是 `w` 最大的窗口，也就是对 F 最有利的一段。

后续所有对比改为同时报"典型（2 秒窗中位）/ 偏大（90 分位）/ 最坏（整段峰峰）"三个口径。
