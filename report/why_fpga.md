# 为什么这个设计需要 FPGA

> 写这一节的起因：评委一定会问"这点运算量，单片机不也能做？"
> 下面先承认哪些理由**不成立**，再给三条成立的，全部带可核验的数字。

---

## 0. 先说实话：这个负载本身不需要 FPGA

每通道每采样点的乘法次数：

| 环节 | 乘法次数 |
|---|---|
| 温和高通（移位） | 0 |
| 矩形窗滑动求和 | 0 |
| 矩形窗归一化 ×1/L | 1 |
| 50 Hz 陷波 biquad | 5 |
| 31 抽头对称 FIR（折叠） | 16 |
| **合计** | **22** |

8 通道 = 176 次乘法。500 SPS 下每个采样周期有 **200,000 个时钟**（100 MHz），
占一个 DSP48E1 的 **0.088%**（单通路）、**0.172%**（双通路）。

**这个运算量一颗 Cortex-M0 就能跑。** 如果作品的卖点停在"我在 FPGA 上实现了
一条滤波链"，这个问题答不上来。下面三条才是真正只有 FPGA 能给的。

---

## 1. 多延迟通路空间并行 —— CPU 做不到的那一条

### 问题的来源

滤波有一条绕不过去的定理：因果 LTI 系统的幅度和相位不独立
（Bode 增益—相位关系，最小相位系统下 `ln|H|` 与 `arg H` 是希尔伯特变换对）。
要压住 0.5 Hz 以下的基线漂移，带内相位就被锁死；唯一能改相位而不动幅度的
是全通环节，而有用的全通环节就是**纯延迟**，所需延迟按 `1/fc` 标度。

于是出现一个硬取舍：

| | 延迟 | 逐拍 ST60 误差 |
|---|---|---|
| 不补延迟（D=0） | 30 ms | 0.152 mV |
| 补延迟（D=159） | 348 ms | 0.082 mV |

**诊断要精度，闭环要速度，而它们要的是同一份数据。**

### FPGA 的解法

同一组采样同时跑两条不同延迟的链路，**每通道独立配置 D**：

```
            ┌─→ 延迟线 D=0   → 陷波 → FIR →  30 ms → 实时显示 / 报警 / 闭环控制
原始码 → 温和高通 → 矩形窗基线估计 ─┤
            └─→ 延迟线 D=159 → 陷波 → FIR → 348 ms → ST 测量 / 波形存档 / 模型推理
```

温和高通和矩形窗基线估计**两条路共享**，只有延迟线、陷波、FIR 各一份。

增量成本：每通道多 21 次乘法（矩形窗归一化那 1 次是共享的）。
8 通道双通路合计 **344 次 / 200,000 时钟 = 一个 DSP48 的 0.172%**。

**关键不在成本，在于：低延迟通路的延迟，不因为旁边多了一条诊断通路而增加
一个时钟。** 两条链在空间上并存，各自独立流水。

在 CPU 上做同一件事：多跑一条链就是多一份计算时间，而且中断、缓存、调度都
会给延迟引入抖动 —— 你能保证平均延迟，保证不了**每一个**采样点的延迟。

这是空间并行对时间复用的本质差别，也是这个作品最硬的 FPGA 论据。

## 2. 通道数可扩展性 —— 瓶颈在存储不在运算

### 算力上限

```
一个 DSP48E1：200,000 / 22 ≈ 9,000 通道（单通路）；/ 43 ≈ 4,650 通道（双通路）
XC7Z020 共有 220 个 DSP48E1
```

### 存储上限（实际瓶颈）

每通道：

| 用途 | 位数 |
|---|---|
| 矩形窗历史 320 × 24 bit（**兼作各通路的延迟线**） | 7,680 |
| 滑动和 + 温和高通累加器 | 68 |
| *（两条通路共享）* | **7,748** |
| 陷波状态 4 × 24 + FIR 历史 31 × 24 bit | 840 |
| *（每条通路各一份）* | **840** |

写 HLS 时发现一处可省：`DC_DELAY_MAX`(192) < `DC_BOX_L`(320)，
矩形窗历史里已经存着最近 320 个 yg，**延迟抽头直接在这块 RAM 上多开一个读口**
就行，不必另开延迟线 —— 每通道每通路省 4,608 bit。
而 BRAM 本来就是双端口的：一个口读滑出窗口的样本，一个口读延迟抽头，正好用满。

- 单通路：7,748 + 840 = **8.6 kbit/通道**
- 双通路：7,748 + 2×840 = **9.4 kbit/通道**

XC7Z020 片上 BRAM = 140 × 36 kbit = 4.9 Mbit：

| | 理论通道数上限 |
|---|---|
| 单通路 | **约 570** |
| 双通路 | **约 520** |

（BRAM 按块分配，实际会少一些。）

**结论可以量化地写进报告：这个架构在 PYNQ-Z2 上支撑约 520 条双通路，
瓶颈是片上存储而不是算术单元，而且通道数增加不引入任何额外延迟。**

对高密度肌电阵列、多导联 EEG 这类场景，CPU 的耗时随通道数线性增长并撞墙；
FPGA 在 BRAM 用完之前，延迟是常数。

## 3. "零乘法器"是针对 FPGA 资源结构做的决策

直流阻断这一级用**移位 + 滑动求和**实现，整级只有 1 次乘法（归一化 1/L），
而等效效果的常规做法是一条长 FIR。

这个取向在 CPU 上**毫无意义** —— CPU 里乘法和加法同样快，刻意避开乘法不省
任何东西。它只在 FPGA 上成立：

- LUT 和进位链加法器在 FPGA 上很便宜且数量巨大
- DSP48E1 稀缺（XC7Z020 只有 220 个），是真正要省的资源
- 把算力从 DSP 挪到 fabric，等于把稀缺资源让给更需要的地方

同理，`L=320` 不是 2 的幂这件事也是按 FPGA 代价权衡的：纯移位能省掉那 1 次
乘法，但 `L=256`（512 ms，短于一个心拍）会让 ST 系统性读低 0.068 mV —— 临床
判读阈值是 0.1 mV。**用 1 次乘法换 0.04 mV 的 ST 精度，在这个器件上是划算的。**

## 4. 确定性延迟

FPGA 的延迟以时钟周期计，没有中断、没有缓存缺失、没有调度器。
本设计的延迟是可以写成常数的：

```
诊断通路  = DC_DELAY_ECG  + FIR_DELAY = 159 + 15 = 174 点 = 348 ms
低延迟通路 = DC_DELAY_FAST + FIR_DELAY =   0 + 15 =  15 点 =  30 ms
```

实测 R 峰相对零相位参考的偏移 174 点，与按结构算的一致；每拍偏移的标准差
2.35 点，和不做延迟补偿的方案（2.64 点）相同 —— 说明是整体平移而非波形畸变。

对闭环控制场景，"最坏情况延迟"比"平均延迟"更重要，这一点 CPU 给不了保证。

## 5. 不要在报告里说的话

以下说法**不成立**，写上去会被问倒：

| 不要说 | 为什么不成立 |
|---|---|
| "FPGA 算得快，所以用 FPGA" | 8 通道双通路只占一个 DSP48 的 0.172%，速度完全不是瓶颈 |
| "单片机做不了这个滤波" | 做得了。Cortex-M0 级别就够 |
| "用了自适应/AI 滤波" | 定稿是纯 LTI。自适应方案测过并被否证（见 §6） |
| "延迟 30 ms，实时性好" | 诊断通路是 348 ms。只有低延迟通路是 30 ms，且它不做 ST 测量 |
| "完全消除了基线漂移" | 残留 2 秒窗中位 0.040 mV，不是零 |

## 6. 证据与保留

### 支持上述结论的实测

| 结论 | 证据 |
|---|---|
| 延迟补偿是有效成分 | 2×2 消融：拆掉自适应加权层指标不变，拆掉延迟补偿全部塌回基准 |
| 矩形窗优于一阶 IIR | 群延迟平坦度 1.00 vs 11.25 倍；逐拍 ST60 误差 0.082 vs 0.119 mV |
| L 要接近一个心拍 | L=256 偏差 −0.068 mV，L=320 降到 −0.028 mV；实测 RR 824/878 ms |
| 自适应不收敛 | LMS 权重 30 秒内在 ±27~86% 间游走，电极脱落时冲到稳态的 23 倍 |

### 必须如实写出的保留

1. **数据量**：两段 60 秒、**一个被试**。所有排名都建立在 120 秒数据上。
2. **"验证段"已不是留出集**：调参过程中被反复查看并据以选参，存在选择泄漏。
3. **参考基准不是真值**：形态指标是对 `filtfilt` 的相似度，不是临床正确性。
   `filtfilt` 自身的 0.5 Hz 高通也会削 T 波，所以"占参考百分比"可能超过 100%。
4. **候选之间已无法分辨**：延迟 124~460 ms 区间内逐拍 ST60 误差全在
   0.075~0.079 mV，差异在噪声内。"这是最优"不能讲，只能讲"在可分辨范围内到顶"。
5. **未诊断的异常**：部分参数组合出现 P 段相关塌陷（0.65 / 0.38 / −0.55），
   原因未查清。
6. **低延迟通路未做逐拍指标全测**：只测了 D=0 和 D=159 两端。

### 下一步最该做的不是调参

再采几段数据（不同天、不同电极位置、含走动与深呼吸），比任何进一步调参都更能
支撑上述结论。采集板电池供电即可，几小时的工作量。
