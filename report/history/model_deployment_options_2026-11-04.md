# 心拍模型部署方案核查（2026-11-04）

核查权重：`模型训练/模型改进/experiment_09/runs/six_db_seed0/best.pt`；配置为同目录config.json。读取权重时仅用白名单元数据解析，没有依赖PyTorch执行反序列化代码。权重为state_dict，张量形状与experiment_08/run.py的Network('multi')及experiment_09的八输出替换一致。未在本次实际推理或修改板端程序。

## 已确认输入契约

- 195608个FP32参数，张量存储782432字节；约36874592 MAC/拍（按Conv1d和Linear权重计算，不含归一化、激活、池化等）。这不是板端性能实测。
- 波形输入[batch,2,205]，256 Hz，anchor=77：第一通道是有效点内逐拍均值/标准差归一化的波形，第二通道是0/1有效掩码。窗口约R前0.301秒至R后0.496秒，掩码界限按前后相邻心拍中点裁剪；不能将205个500 Hz点直接输入。
- 另有[batch,8] RR特征。设a=max(前RR,.05)、b=max(后RR,.05)、ref=max(最近最多8个历史RR的中位数,.05)、last为再前一个RR（边缘回退按训练代码），lo/hi为256 Hz中点边界，特征为[log(a),log(b),min(a/ref,5),min(b/ref,5),log(ref),min(a/b,5),log((hi-lo)/256),log(max(last,.05))]。按config.json各维均值/标准差标准化后截断到[-8,8]。
- 输出顺序严格为A/F/L/N/R/S/V/|。网络含三路卷积、空洞残差卷积、GroupNorm、掩码池化、门控及RR分支。GroupNorm依赖当前输入，不能按固定统计量直接折叠成卷积。
- 训练预处理为原采样率0.5～40 Hz三阶Butterworth双向带通，接50 Hz Q30双向陷波，再resample_poly到256 Hz。使用参考标注定位及未来RR，而不是自动R峰检测。

## 延时识别定义

当前权重至少需等到下一拍被定位，才能形成后RR与中点掩码。不能以过去RR代替未来RR而声称训练输入等价。下一拍始终不来时，应保持待定或超时提示，不能伪造后RR。

可做两种显示：实时波形照常滚动，识别完成后回填过去尖峰的标签；或把波形本身延后固定数秒，标签与尖峰一起出现。后一种视觉上整齐，但慢心率/漏检可能仍超过固定延时，应允许待定。标签必须绑定原始样本索引，经过500→256 Hz重采样、滤波延迟及环形缓存时保持可追溯。

双向滤波的全记录输出不能在无限流上严格实时复现。使用带左右重叠上下文的有限窗口、只取稳定中部，可做有延时的近似；右上下文长度应在留出数据上测定，而不是用sosfiltfilt的最小padlen作为稳定性保证。

建议先试2～3秒延迟预算并实测，它是设计目标不是已达到指标。等待后RR、双向滤波上下文、自动检测、重采样、推理及显示调度都计入端到端延时。启动时还需要历史RR积累；训练有历史不足的边缘处理，可复用并标记预热。

## 实现路线

| 路线 | 是否保持现有权重 | 是否脱机 | 主要工作与边界 |
|---|---|---|---|
| 电脑识别，PYNQ采集/HDMI | 是 | 否 | 最容易做参考实现；数据发电脑，返回带原始样本索引的标签；用于验证自动检测、预处理及结果回填 |
| ARM PS识别，PL保持采集/显示 | 是 | 是 | 推荐首版；从原始ADC环形缓冲分支到模型预处理，不直接串接现有HLS滤波波形；双核Cortex-A9上先测单拍耗时，确认32位运行时支持 |
| PL加速卷积，PS处理RR/归一化/控制 | 可逐步保持数值或做定点近似 | 是 | 自定义HLS时分复用卷积，权重/中间激活分块；GroupNorm、门控、掩码池化也需实现或合理划分；需量化和逐层误差验证，不能直接烧.pt |
| FINN/Brevitas量化网络 | 通常需改造、量化微调 | 是 | 官方工具要求量化导出及受支持算子；不是任意ONNX都能编译，当前GroupNorm等算子需先核查，工作量高于CPU首版 |
| 训练仅用历史信息的因果模型 | 否，需新权重 | 是 | 去掉未来RR依赖，使用因果滤波重新训练/评估；可缩短等待，但不是部署当前best.pt的等价实现 |

PYNQ-Z2为32位ARMv7/Cortex-A9平台，不能安装ARM64包；选择ONNX Runtime、PyTorch或其他C++运行时时须核实具体版本的ARM32构建和算子支持。可用定制C++推理作为备选，但维护成本需计入。官方资料：https://onnxruntime.ai/docs/build/inferencing.html ，https://finn.readthedocs.io/en/latest/faq.html ，https://www.sparkle-embedded.com.tw/en/PYNQ-Z2 。

## 推荐顺序

1. 在电脑重建该权重参考推理与精确输入契约，在现有公开库留出样本验证导出前后logit一致性。
2. 用本次真实ADC记录做自动R峰、RR、有限上下文预处理与延时回放。无专家标签的自采数据只能验链路与稳定性，不能证明八类准确率。
3. 移到PS后台工作进程，采集/显示继续独立运行；仅一个进程操作FPGA，识别进程经内存队列获取数据并返回结果。先不改bitstream。
4. HDMI增加逐拍标签、待定/置信度及延时提示。标签与界面字库需要扩展，不能仅改Python字符串就让现有RTL自动显示。
5. 仅在PS实测算力或竞赛加速目标需要时，再迁移卷积到PL。比较同一输入、精度、单拍耗时、端到端延时和资源，而不是只报告网络算子速度。

现有训练报告三种子均值中L/R召回很差，A/F/S也有明显限制，97.08%合并准确率不表示八类均可靠。部署演示须保留八类原顺序及其验证边界；类别准确性改进与硬件部署属于不同问题。
