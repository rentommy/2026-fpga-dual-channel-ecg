## 3. 作品目标与系统划分

项目目标是将自制 ADS1292／ADS1292R 心电采集系统与 PYNQ-Z2 结合，在 PL 中实现多通道、双延迟滤波，PS 负责数据组织、显示、心率／波形指标与模型推理。

需要区分两个通道数量：采集器件具备两个模拟采集通道；现行 HLS 核配置为八个逻辑输入通道，每通道两个输出通路。八通道目前通过软件向量验证，尚无八路真实采集证据。现有两份源数据各是一列整数，也不足以证明双导联同步采集已经完成。

前期曾规划 ADS1292 SPI 主机与配置状态机由 RTL 实现，但 `src/rtl/` 目前为空。实际导出的滤波 IP 通过 DDR 缓冲输入，不直接接收 SPI。

## 4. 已有前期成果

暑假汇报记载已完成自制采集板、电源板、STM32 采数、串口传输、香橙派推理与上位机显示，经历了供电隔离、信号隔离、电极位置、接收丢数与线程锁竞争等调试。

汇报给出的历史指标包括：约 499 SPS、七分类测试准确率 95.19%、模型约 190 KB、单次香橙派推理约 130 ms，房性早搏召回率仅约 50.6%。这些是旧平台的历史结果，本次没有训练集、划分清单和运行源码来独立复核。

## 5. 现行滤波方案

现行实现应以 `src/hls/` 与 `chain_hw_v2()` 为准。阶段一的 `k=7` 两级移位高通，以及非线性加权、门控和方案 F，均是历史对照。

| 环节 | 当前参数／实现 |
|---|---|
| 采样率 | 500 SPS |
| 温和高通 | 移位系数 `k=8`，累加器保留八位小数 |
| 基线估计 | 长度 320 的矩形窗滑动和 |
| 归一化 | `×3277` 后带舍入右移二十位 |
| 两路基线回减 | 共用基线估计，分别读取不同延迟抽头 |
| 工频陷波 | 50 Hz，Q=15，二阶 IIR |
| 低通 | 40 Hz，三十一抽头对称 FIR |
| 片内数据／累加器 | 24 位样本，48 位陷波与 FIR 累加器 |
| 预热约定 | 前 543 点输出无效，约 1.086 秒 |

| 通路 | 延迟抽头 | 冲激峰值位置 | 当前用途规划 |
|---|---:|---:|---|
| path 0，文档称诊断通路 | 159 点 | 174 点，即 348 ms | 波形指标、存档等 |
| path 1，低延迟通路 | 0 点 | 15 点，即 30 ms | 实时显示等 |

这两个输出不是同一个滤波结果的简单平移：它们减去的是同一时刻的基线估计。ch2、ch3 当前还配置成两路都取零延迟抽头。

348／30 ms 是当前测试确认的冲激峰值延迟，不能直接等同于包含分块等待、DDR 访问、PS 调度和界面刷新的端到端延迟。IIR 环节的相位也不能仅用这个常数完整描述。

算法选型中的关键经验已经明确：模板相关会掩盖幅度和漂移问题；延迟对齐带来了主要收益；低延迟通路在部分指标上改善，但残留漂移可能更大。后续不应无依据退回已经淘汰的方案，也不应把有限实验结果写成普遍不可能性定理。

## 7. HLS 已完成的实际进展

工具产物确认使用 Vitis HLS 2026.1，目标器件 `xc7z020-clg400-1`，时钟约束 10 ns。有效成果位于 `hls_ecg2/`，不是 README 中旧流程描述的 `build/ecg_filter_hls/solution1/`。

| 资源 | 第一版 `hls_ecg` | 优化后 `hls_ecg2` | 器件可用 |
|---|---:|---:|---:|
| DSP | 304 | **1** | 220 |
| BRAM18K | 18 | **26** | 280 |
| FF | 66,870 | **6,915** | 106,400 |
| LUT | 149,887 | **7,700** | 53,200 |

第一版 DSP 与 LUT 都超出器件容量。优化后 HLS 估计分别占 DSP 0.45%、BRAM 9.29%、FF 6.50%、LUT 14.47%。这些是 HLS 估计，尚非布局布线后的最终用量。

实际起作用的约束在 `hls_fix.tcl`、`hls_export.tcl`：

```tcl
config_compile -pipeline_loops 0
set_directive_allocation -limit 1 -type function ecg_filter_top ecg_filter_sample
set_directive_allocation -limit 1 -type operation ecg_filter_sample mul
```

它们关闭自动循环流水、限制滤波函数实例及内部乘法资源。源码顶层原有 `ALLOCATION` 仍有“找不到 mul”的警告；成功结果依赖上述 Tcl 指令，不能声称仅凭当前源码中的 pragma 就能复现。

最新报告估计周期为 7.300 ns，对应估计 Fmax 136.99 MHz。此值不是已实现频率，也不能把目标周期与估计周期之差直接称为板级时序余量。

`sample_loop` 每次迭代为 1,298 周期，覆盖一个时刻的全部八通道、十六个输出。按实际目标 100 MHz 折算约 12.98 μs，占 2 ms 采样周期的 0.649%。4096 点的报告最大块延迟约 53.192 ms；这是估计处理耗时，不含积攒 4096 点所需的等待。

344 是算法的乘法次数估算，不是最终每点周期数。文档中约四至十块 BRAM、0.17% 处理占用等旧估计需要更新。

## 8. 已导出的可用 IP 与接口

IP 文件：`hls_ecg2/hls/impl/ip/nuaa_ecg_ecg_filter_top_1_0.zip`。

该文件为 196,196 字节，本次 ZIP 完整性检查通过。导出日志记录 2026-10-22 00:18 左右完成打包，内部包含 RTL、组件描述和自动生成的 C 驱动。

接口为 `s_axi_ctrl` 控制、`m_axi_gmem0` 读输入 DDR、`m_axi_gmem1` 写输出 DDR，另有时钟、复位及中断。现有 IP 已自带 AXI 主接口，后续基础连接方案不需要再额外插入 AXI DMA。

| 控制偏移 | 内容 |
|---|---|
| `0x00` | 启动、完成、空闲等状态 |
| `0x10 / 0x14` | 输入缓冲物理地址的低／高三十二位 |
| `0x1c / 0x20` | 输出缓冲物理地址的低／高三十二位 |
| `0x28` | 每通道采样点数 `n_samples` |
| `0x30` | 是否复位滤波状态 `do_reset` |

输入为三十二位整数，按 `[点, 通道]` 交织；输出按 `[点, 通道, 通路]` 交织。PYNQ 驱动仍需实现缓冲分配、缓存同步、超时和状态维护。自动生成的 C 驱动不等于已经写好 Python 应用。

当前顶层没有导出运行时修改各通道 D 的寄存器；可配置性目前主要体现为编译期配置和核心初始化函数，不能宣称已经支持 PS 在线调参。

## 10. 接手时需要纠正的文档与验证问题

### 10.1 正式构建入口尚未更新

`src/hls/run_hls.tcl` 仍使用旧项目流程，没有加入这轮成功的三项约束。历史对话虽承诺重写脚本、移动 pragma 和更新报告，本地文件没有显示这些工作已经完成。

`sim/collect_hls_report.py` 自动搜索旧 solution 路径，并取匹配到的第一份子模块报告；它也把估计时钟周期用于耗时折算。需要明确选择顶层 XML，使用与块长度一致的延迟，并以实际配置时钟换算处理时间，才可作为正式报告生成入口。

### 10.2 FPGA 架构论证存在过度表述

现行实现是单滤波核、单 DSP、多通道及双通路时分处理。`why_fpga.md` 中“两路独立流水”“增加通路不会增加一个时钟”“通道数增加延迟恒定”的叙述，与现有调度不能直接对应。

约 520 通道来自理想存储位数相除，没有体现实际 BRAM 分块、端口、复用和控制代价。当前已综合的是八通道，应将更高通道数标为待验证扩展估算。

### 10.3 波形评价口径仍未完全落实

`sim/experiments/plot_boxcar.py` 的“ST60 RMS／T 峰 RMS”实际调用 `.std()`，计算的是标准差，未包含系统偏差。

同一脚本使用相对 R 峰的固定窗口 `ST=(50,60)` 点，没有逐拍检测 J 点，因此其结果不能直接表述为已经实现严格的逐拍 J+60 ms 测量。脚本亦未统一剔除 543 点预热，与部分现行报告表格的统计口径不同。

因此本文不把各文档中不同版本的 ST／T 误差数字拼成一套“已复现指标”。这不推翻定点代码与黄金参考的一致性，但限制了波形测量正确性的结论。

### 10.4 模型预处理路线没有最终闭合

历史记录指出模型训练使用四阶 0.5–34 Hz 双向滤波；现行 PL 链使用因果滤波与 40 Hz FIR。早先曾决定在 PS 单独复刻训练预处理，而新文档又把模型推理安排到诊断通路，尚无现行模型对比实验支持最终路线。

`chain_orig_zerophase()` 本身是三阶 0.5–40 Hz 对照，也不能直接当成已复刻的模型训练预处理。需要恢复原训练定义，再决定保留 PS 预处理还是重训模型。

### 10.5 数据与异常覆盖有限

两份源数据分别为 30,034 点和 30,027 点，按 500 SPS 约六十秒；文档记载来自同一被试，所谓验证段也已参与多轮调参。

第一份数据第一行是 `402`，之后大多为较大的负整数。历史记录推断它来自串口首行被截断；当前文件仍保留该值。后续接收器需处理首个半行，不能未经证据静默改写原始采集数据。

文档记载异常／电极脱落可造成很大输出，但当前没有对应保护。ADS1292 手册也提供 LOFF 状态与检测机制，可与信号质量检测共同评估，不必预设只能使用 EMRMS。

## 12. 建议继续推进的顺序

1. 固定当前有效 IP、综合报告与成功构建脚本，统一正式入口；补精确位宽 C 仿真和适量 C/RTL 对比，确认当前硬件行为。
2. 用该 IP 搭建最小 Vivado 系统，正确配置 PS、时钟复位、控制口与 DDR 通路，生成 `.bit/.hwh`，保留实现资源及实际时序报告。
3. 在 PYNQ 上先回放现有文件，验证缓冲布局、缓存同步、跨块状态、复位和输出与参考的一致性。这个里程碑不依赖实时采集接口先完成。
4. 接入真实采集，确认保留 STM32 中转还是实现原计划的 PL SPI；按最终方案补双通道、采样完整性、导联状态及恢复测试。
5. 完成显示与波形指标，恢复并验证模型预处理，补独立采集数据。
6. 整理通用技能包、更新报告与 README，形成陌生队伍可从零复现的提交包。

接手协作方式沿用历史记录中用户明确提出的偏好：解释一次聚焦一个概念，说明代码和参数的依据，让用户能理解并参与判断。需要赶通流程时给出明确检查点，同时保持对“历史说法”和“实际证据”的区分。
