## 分类

### `dc_block_v1/` —— 旧定稿：移位级联高通 k=7 ×2 级

| 文件 | 当初决定了什么 |
|---|---|
| `decide_dc_block.py` | 移位位数 k 与级数，靠注入 2 mV / 0.2 Hz 呼吸漂移标定 |
| `evaluate_chains.py` | 候选链对比总表，当年"表里的数字直接进设计报告" |

**被什么取代**：`yg - 矩形窗均值` 是一个线性相位 FIR 高通，
用滑动和实现只要 1 次乘法（归一化），而级联移位高通的群延迟随频率变 11 倍。
逐拍临床指标上：ST60 误差 0.1236 → 0.0770 mV，T 峰 0.1721 → 0.1184 mV，
典型残留漂移 0.190 → 0.040 mV。

**注意两处**：
- `evaluate_chains.py` 的候选表里仍把 `k=7, 2级` 标成"←定稿"，**这个标签现在是错的**；
  它比的全是移位链变体，没有矩形窗那一行。
- `decide_dc_block.py` 第 116~128 行的 Q1.15 小节有已知缺陷：`quantize()` 没有范围检查，
  系数溢出时不报错而静默给出错误结果。归档时未修。

**方法仍可复用**：注入已知幅度与频率的漂移再量残留，是标定滤波器的正确做法，
比拿实测数据直接看"像不像"可靠得多。

### `nonlinear_gated/` —— 非线性与门控探索（全部否证）

想法都是同一条线：既然线性时不变滤波器在"低延迟 / 保形态 / 强去漂移"之间
必须取舍，那就用非线性或时变手段跳出去。

| 文件 | 试过的办法 |
|---|---|
| `nonlinear_dc.py` | 双链路按检测量渐变合并；QRS 期间冻结基线更新。**同时是本目录的指标库** |
| `gated_dual.py` | 只在强阻断链上门控 —— 治病因而不是治症状 |
| `slope_hold.py` | 门控期间零阶保持 vs 按斜率外推 |
| `gate_from_gentle.py` | 门控触发源从原始数据换成温和链，做成真正的 R 波检测器 |
| `sweep_aggressive.py` | 扫强阻断链的 k 和级数，把拐点推到 T 波频率之下 |
| `var_timeconst.py` | 变时间常数单链 —— 把"需要合并"这件事本身消掉 |
| `anchor_and_selfres.py` | 等电位点锚定；自残基线回减 |
| `filtered_inject.py` | 注入量先低通，只让慢基线修正进输出，把 T 波挡在外面 |
| `switch_transient.py` | 渐变合并会不会在切换时产生伪迹。**提供 R 峰匹配 `match_peaks`** |
| `plot_dual.py` | 双链合并的可视化 |

**为什么全部否证**：决定性的是一次 2×2 消融（k_g=7, k_lp=7, D=116）——
去掉自适应权重 `w`，结果几乎没变（0.051 → 0.041）；
去掉延迟补偿，一切塌回旧定稿的**数值完全相同**的值。
也就是说，这一路所有收益的**唯一有效成分是延迟对齐**，非线性层是死重。

更根本的原因是 Bode 增益—相位关系：因果最小相位系统的 `ln|H|` 与 `arg H` 是
希尔伯特变换对，幅度一定，带内相位就锁死了。唯一有帮助的全通环节是**纯延迟**。
所以"低延迟 + 保形态 + 强去漂移三者不可兼得"是定理，不是没调好。

另外实测否证了在线 LMS：权重范数 30 秒内 1.019 → 0.829 → 2.180 → 2.617 → 2.092
（相对标称值 ±27~86%），电极脱落时输出冲到 1486 mV，是纯延迟 LTI（270 mV）的 5.5 倍。

### `plan_f/` —— 方案 F：一阶 IIR 基线估计 + 自适应权重 + 延迟对齐 D=200

| 文件 | 作用 |
|---|---|
| `align_delay.py` | 发现 F 的基线估计有滞后后补偿延迟的扫描（用户提出） |
| `plot_F.py` / `plot_F2.py` | F 原版与延迟对齐版（D=80）的输出图 |

**被什么取代**：和定稿只差一个零件 —— **基线估计器**。
一阶 IIR 的群延迟 `tau(f) = tau0/(1+(f/fc)^2)`，k=8 时在 0.05~1 Hz 之间
从 249 点变到 22 点，**变 11.25 倍**，一个固定 D 只能对齐一个频率。
半高斯 σ=180 是 2.83 倍。**矩形窗 L=400 是 1.00 倍** —— 群延迟恒为 `(L-1)/2`，
一个 `D` 把所有频率一次对齐。这就是换矩形窗的全部理由。

### `two_record_sweep/` —— 双段交叉验证与候选总表

| 文件 | 作用 |
|---|---|
| `cross_validate.py` | 换一段实测数据，看调出来的参数还成不成立 |
| `joint_sweep.py` | 双段联合扫描，只认两段都站得住的配置 |
| `final_compare.py` | 所有候选用同一套指标、同样两段数据重跑 |

**为什么结论不能用了**：两个原因，第二个更要紧。

1. 候选集是旧的 —— 全是移位链和方案 F 的变体，没有矩形窗。
2. **度量方法本身有盲区。** 这三个脚本的主指标是心拍模板相关，
   而模板相关对基线漂移和幅度**都盲**：逐拍平均把漂移抵消掉，L2 归一化把幅度抵消掉。
   换成逐拍临床指标（每拍以自己的 PQ 段为基准量 ST60 与 T 峰，与零相位参考配对）之后，
   **候选排序直接反过来了**。这个坑在定稿前踩了四次。

扫描框架和"只认两段都成立"的原则仍然对，换指标重跑即可。

### `boxcar_tuning/` —— 矩形窗调参中被否的中间值

`boxcar_L256_D127.png`：L=256（512 ms）。

**为什么否**：窗长必须取到约一个心拍（实测 RR 824 / 878 ms）。
窗比一拍短时，窗里装着 QRS 和 T 波本身，基线估计被顶高，减完造成 ST 系统性读低：
L=256 偏差 **−0.068 mV**，而 **0.1 mV ST 压低就是临床判读阈值** —— 会造成假阳性。
L=320（640 ms）降到 −0.028 mV，定稿取 320。

附带的好处：矩形窗的频谱零点在 `fs/L`，L ≈ 一个 RR 时正好把心搏基频从基线估计里零掉。
